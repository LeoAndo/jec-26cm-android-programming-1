ANDROID PROGRAMMING 1 / 共通資料・授業サポート

困ったとき

コードが赤くなった、アプリが動かない、原因が分からない。
エラーに向き合い、自分で解決するための調べ方をまとめています。

  1. 1. エラーが起きたときの調べ方
  2. 2. 共通資料を活用する
  3. 3. どうしても解決しないときは（完成プロジェクトの確認）

1. エラーが起きたときの調べ方

プログラミングでエラーが出るのは自然なことです。エラーメッセージには「どのファイルの何行目で、何が問題か」が必ず書かれています。焦らずに上から順に確認しましょう。

  1. 各単元の「困ったとき」表を確認する
    教科書の末尾にある「困ったとき」には、その単元でよくある間違いと確認場所がまとまっています。
  2. 最初の赤い行を見る
    エラーが何行も出ているときは、一番上の「最初の赤い行」を直します。最初の1つを直すと、あとのエラーがまとめて消えることがよくあります。
  3. 直前のSTEPと見比べる
    手順を1つ飛ばしていないか、大文字・小文字やスペル（綴り）が教科書と違っていないかを確認します。
  4. 先生に質問するときは
    「STEP番号・編集したファイル・最初の赤い行・押した順番」を伝えると、原因が早く分かります。

2. 共通資料を活用する

エラーの種類に応じて、次の共通資料を参考にしてください。

困っていること参考にする共通資料
赤い文字が出てシンボルが見つからないと言われる共通資料：Auto Import で必要なクラスを読み込めているか確認します。
アプリが起動時に落ちる、実行中にエラーになる共通資料：Logcat で赤いエラーログ（例外）を確認します。
エミュレータが起動しない、動かない共通資料：エミュレータ で再起動や設定を確認します。
画面の余白が消える、キーボードが隠れる共通資料：開発Tips でレイアウトの注意点を確認します。
Android Studioのバージョンが違う共通資料：ちがうAndroid Studioのバージョンで進めるとき を確認します。

3. どうしても解決しないときは（完成プロジェクトの確認）

どうしても自分のコードの間違いが見つからないときや、アプリ本来の動きを確認したいときは、先生が作った完成プロジェクト（見本）を開いて自分のコードと見比べることができます。

完成プロジェクトは「答え合わせ用」です

完成プロジェクトからコードをそのままコピーしたり、完成プロジェクトを改造して提出しても、自分の課題の提出にはなりません。見本で違いを確認したら、必ず自分で作ったプロジェクトに戻り、自分の手で修正してください。

  1. Android Studioのメニューから File → Open を選びます。
  2. 書類（Documents）にある教材のフォルダ（android1-student-materials-日付）を開きます。
  3. その中にある samples フォルダを開き、該当する単元のフォルダ（例：A02CalcGame）を選んで Open をクリックします。
  4. Gradle同期が終わったら、Runして正しい動きを確認したり、エラーが出ているファイルと見比べます。
  5. 確認が終わったら見本を閉じ、自分のプロジェクト（Documents/Android1/単元名）を開き直して作業を続けます。

取り違えに注意

見本と自分のアプリは同じプロジェクト名です。ウィンドウ上部のタイトルバーに表示される保存先パスを確認し、見本のほうを編集してしまわないよう注意しましょう。
