はじめに読んでください

この授業は、1人の先生が全員の実習を見ています。環境が人によって違うと、うまく動かないときの原因が「教科書のとおりに書けていない」のか「環境の違い」なのかを、その場で切り分けられません。実習の時間内に全員をフォローするために、基準となる環境を1つ決めています。

教科書は、その基準のバージョンで実際に動くことを確認して作っています。貸与パソコン以外や規定と違うバージョンでは、この確認が取れていません。

このページは、それでも自分の環境で進めたい人のための手がかりです。確実に授業についていきたい場合は、規定のバージョンに合わせてください。

1. サポートの範囲

1-1. 基準の環境と、それ以外

扱い
貸与パソコン＋規定のバージョン基準の環境です。教科書はこの環境で動作を確認しています。実習中のフォローもこの環境が前提です。
自分のMac、または規定と違うバージョン動作確認をしていません。このページを手がかりに自分で読み替えます。実習中に質問しても、時間内に解決できないことがあります。
Windows授業では使いません。教科書はmacOS前提で書かれています。

迷ったら基準の環境へ

環境の違いが原因の問題は、切り分けに時間がかかります。90分の実習の中で解決できないことも多く、そのぶん教科書を進める時間が減ります。困ったら早めに貸与パソコンへ戻してください。教科書のとおりに進めば、同じものができます。

3. 読み替えのポイント

3-1. 画面の見た目が違う

Android Studioは版が上がると、ウィンドウの文言や項目の並びが変わることがあります。

合わせ方

スクリーンショットの見た目ではなく、「何を選ぶか」で合わせます。2-2の表の4項目さえ同じなら、画面の並びが違っても同じプロジェクトができます。項目が見つからないときは、ウィンドウ内を探すか、Previous で1つ前に戻って確認します。

テンプレートの名前が変わっている場合は、Views という語が入っているものを選びます。Empty Activity（Viewsが付かないもの）はJetpack Composeという別のしくみで、教科書のXMLと合いません。

3-2. 完成プロジェクトを開くと更新をすすめられる

新しいAndroid Studioで完成プロジェクトZIPを開くと、Android Gradle Pluginのアップグレードをすすめる案内（AGP Upgrade Assistant）が出ることがあります。

授業中は更新しません

更新すると build.gradle.kts などの中身が書き換わり、教科書に載っているコードと差が出ます。案内が出ても閉じてください。完成プロジェクトは「答え合わせ用の見本」なので、そのまま読めれば十分です。

自分で作るプロジェクトのほうは、新しいAndroid Studioが選んだバージョンのままで構いません。教科書が指定しているのは2-2の4項目だけです。

3-3. エミュレータの名前が違う

自分のMacには jec_26cm_android1_Pixel 9a がありません。共通資料：エミュレータの準備とアプリの実行の手順で、同じ設定のものを自分で作ってください。名前は同じにしておくと、教科書の記述をそのまま読めます。

3-4. Quail 4 との違い（実際に比べた結果）

教員が Android Studio Quail 4 で同じ設定のひな形プロジェクトを作り、Panda 2 のものと1ファイルずつ比べました。結果は次のとおりです。

同じだったもの

ファイル結果
MainActivity.java完全に同じ（パッケージ名の行を除く）
activity_main.xml完全に同じ
themes.xml同じ（テーマ名を除く）
Minimum SDKどちらも minSdk = 31。ウィザードで API 31 を選べば同じになる

ここが大事です

教科書で入力するコードは、Quail 4 でもそのまま使えます。ひな形の MainActivity.java も activity_main.xml も中身が同じだからです。android:id="@+id/main" も、インセットの処理も、Panda 2 と同じ形で作られます。

違ったもの

違いはすべてビルドの設定にありました。授業では触らない部分です。

Minimum SDK だけは自分で選びます

教科書は API 31 を前提にしています。新規作成のときに自分で API 31 を選べば、Quail 4 でも minSdk = 31 になります（比較に使ったひな形で確認しました）。作ったあとで確かめるときは app/build.gradle.kts の minSdk を見ます。

上の表の違い（AGP・Gradle・compileSdk・targetSdk・R8のファイル名・ライブラリ）は、そのままで構いません。教科書はこれらに依存していません。新しいバージョンが選んだ値のまま進めてください。

なお Quail 4 のひな形は、そのまま assembleDebug が通ることを確認しています。

3-5. Javaのバージョンのこと（JVM / toolchainVersion / compileOptions）

先に結論です。教科書に出てくるJavaの書き方は、Quail 4 でもそのまま使えます。

Javaは2か所で使われています

まぎらわしいのですが、Androidアプリ作りでは「Java」が2つの役割で出てきます。調べるときに使う言葉もあわせて載せます。

どこで使うJavaか設定の名前と場所
①自分が書くコードのJava。MainActivity.java に書く var やラムダ式など。compileOptions の sourceCompatibility / targetCompatibility
（app/build.gradle.kts）
②アプリを組み立てる道具（Gradle）を動かすためのJava。この実行環境を JVM と呼びます。学生が直接書くことはありません。toolchainVersion
（gradle/gradle-daemon-jvm.properties）

Panda 2 と Quail 4 で違うのは、②のほうだけです。

Panda 2 | 2025.3.2Quail 4
① 自分が書くコードのJava
（compileOptions）		JavaVersion.VERSION_11JavaVersion.VERSION_11（同じ）
② Gradleを動かすJVM
（toolchainVersion）		2125

だから、コードの書き方は変わりません

①の compileOptions が同じ Java 11 なので、教科書のコードをそのまま入力して大丈夫です。「Javaのバージョンが違うから書き方も変えないといけないのでは」と心配する必要はありません。

起きること：最初のビルドに時間がかかります（Gradle toolchain のダウンロード）

gradle/gradle-daemon-jvm.properties には「②にどのバージョンを使うか」が toolchainVersion として書き込まれています。そのバージョンが自分のパソコンに無いと、Gradleが自動でダウンロードします（Gradle の toolchain 自動プロビジョニングという仕組みです）。

授業で配る完成プロジェクトは toolchainVersion=21 です。Quail 4 が持っているのは25なので、完成プロジェクトを開くとJDK 21 のダウンロードが始まることがあります。

こうなったときは、待ってください

  • 初回のビルドだけ、数分かかることがあります。止まってしまったわけではありません。
  • このときインターネットにつながっている必要があります。つながっていないと失敗します。
  • 2回目からは速くなります。一度ダウンロードしたものが ~/.gradle/jdks に保存され、使い回されるためです。

画面下のビルドの表示に Downloading や toolchain という文字が出ていれば、この待ち時間です。エラーを調べるときは Gradle toolchain や toolchain auto-provisioning という言葉で検索すると情報が見つかります。

自分で新しく作ったプロジェクトのほうは、Quail 4 が自分の持っているバージョン（toolchainVersion=25）を書き込むので、このダウンロードは起きません。

先生向け：確認した内容

各プロジェクトの gradle/gradle-daemon-jvm.properties の toolchainVersion を比較しました。A01〜A09 と Panda2JavaEmptyViewActivity はすべて 21、Quail4JavaEmptyViewActivity は 25 です。app/build.gradle.kts の compileOptions は、どちらも sourceCompatibility / targetCompatibility とも JavaVersion.VERSION_11 で一致しています。

JDK 25 が入っていないMacで Quail4JavaEmptyViewActivity をビルドしたところ、Gradleが Eclipse Adoptium 25.0.3 を ~/.gradle/jdks へ自動取得したうえで assembleDebug が成功しました（2026年9月17日）。

4. それでも合わないとき

4-1. 判断のしかた

状況どうするか
画面の文言が違うだけ3-1のとおり、選ぶ内容で合わせる。
教科書のコードを入れても赤いエラーが消えない各単元の「困ったとき」を見る。それでも直らなければ規定のバージョンに切り替える。
Runできない・ビルドが通らない規定のバージョンに切り替える。環境の違いが原因のことが多く、授業時間内では切り分けられません。
提出期限が近い迷わず貸与パソコンで作り直す。教科書どおりに進めば同じものができます。

4-2. 確かめたこと・確かめていないこと

内容
確かめたことQuail 4 で作ったひな形プロジェクトと、Panda 2 のものを1ファイルずつ比べた（3-4の表）。Quail 4 のひな形が assembleDebug で通ること、そのときGradleが JDK 25 を自動取得したこと（3-5）も確認した。
確かめていないこと各単元のSTEPを最後まで通して進めた動作は、Quail 4 では試していません。Quail 4 以外のバージョン（さらに新しい版など）も試していません。3-1〜3-3の読み替えは、一般的な注意点としてまとめたものです。

気づいたことを教えてください

ちがうバージョンで進めて気づいたことがあれば、先生に知らせてください。次の版でこのページに反映します。そのとき「Android Studioのバージョン」「起きたこと」「教科書のどのSTEPか」の3つを伝えてもらえると助かります。
