教員用ガイド
BillSplitter

ArrayListで参加者を集め、A06で学んだ配列の受け渡しで画面を切り替え、教材に入れてある計算クラスを呼ぶ前に入力チェックを書く。「他人が作ったクラスを使う」「前提条件は呼び出す側が守る」を体験させる進行案です。90分×3コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/bill-splitter/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A07BillSplitter、パッケージは jp.ac.jec.a07billsplitter です。
  • 別に配るファイルはありません。STEP 07で使う BillSplitter.java は教材のフォルダに同梱してあり（実体は docs/bill-splitter/downloads/BillSplitter.java）、学生がFinderでコピーします。手順は、書類の教材フォルダ（android1-student-materials- ＋日付）から docs → bill-splitter → downloads を開き、Android Studioの jp.ac.jec.a07billsplitter に貼り付ける形です。STEP 01の前に、教材のフォルダを「書類」へ移動できているか確認させます（共通資料：はじめの準備の1.）。
  • STEP 02で使う title_img.png も、同じ docs/bill-splitter/downloads/ に同梱してあります。学生が同じ手順でFinderからコピーし、Android Studioの app/src/main/res/drawable に貼り付けます。同じフォルダに完成プロジェクトのZIPと BillSplitter.java も入っているので、STEP 02では title_img.png だけを選ばせます。
  • 完成版は Documents/Android1/samples/A07BillSplitter に置きます。見本と学生のアプリは同じパッケージ名のため、端末上では同じアプリを上書きします。Run前にウィンドウの保存先を確認させます。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a を縦向きで使います。
  • アプリの実行にインターネット接続は不要です。この単元ではLogcatを使いません。結果はすべて画面に表示されます。

今回の仕様上の制約

各単元では画面回転時のデータ保持と横画面のレイアウトを扱いません。回転などでActivityが作り直されると、登録した参加者と計算結果は初期状態に戻ります。考え方と対処法は共通資料：開発TipsのC章に掲載しています。金額の入力欄は android:inputType="number" と android:maxLength="9" で、半角数字9桁までに制限しています。参加者の人数に上限はありませんが、教材が想定するのは数人から十数人です。

2. この単元の教材方針

方針理由授業での扱い
BillSplitter.java は完成品として渡し、学生には実装させないこの単元の主題は画面遷移と入力チェック。端数分配のアルゴリズム、NumberFormat、StringBuilder は主題から外れる。自力実装させると1円ずれたまま完成したと思い込む誤りが起きやすい。「中身は読まなくてよい。使い方だけ覚える」と明言する。STEP 07の表で、渡すもの2つと戻り値だけを押さえる。
タイトル画像は別に配布せず、教材のフォルダからFinderでコピーさせる。ダウンロードボタンにはしない以前は「先生から配られた」とだけ書いてあり、教員が別にファイルを配らないと学生が先に進めなかった。そこで同じ画像を docs/bill-splitter/downloads/ に置き、教科書のボタンからダウンロードさせた（issue #123）。ところが、教科書をファイルとして開いていると（file://）、ブラウザは download の指定を無視するので、ボタンを押しても保存されず、画像がブラウザに表示されるだけだった。学生は教材のフォルダをすでに「書類」へ展開しているので、そこを開いてコピーさせるほうが確実で、ブラウザの種類にも左右されない（issue #192）。置いた画像が完成プロジェクトの画像とバイト単位で一致することと、教科書のSTEP 02に置き場所とファイル名が書いてあることを python3 scripts/check-teaching-materials.py が検査するので、二重管理でずれる心配はない。完成プロジェクトの画像を差し替えたら、cp A07BillSplitter/app/src/main/res/drawable/title_img.png docs/bill-splitter/downloads/ で置き直す。STEP 02に入る前に、教材のフォルダを「書類」へ移動できているか確認する。フォルダ名の日付は配った回で変わるので、教科書には日付を書いていない。「今日はこの日付のものを使います」と口頭で指定する。downloads には完成プロジェクトのZIPと BillSplitter.java も入っているが、STEP 02では選ばせない。Copyダイアログの画像（drawable-copy.png）は撮り直していない。Copy file のうしろに写っているコピー元は先生の保存先で、学生の画面では教材のフォルダの中の場所が出る。確認させるのは New name と To directory で、どちらもコピー元には左右されない。
BillSplitter.java は別に配らず、教材のフォルダからFinderでコピーさせる以前は「先生から配られる」とだけ書いてあり、教員が別にファイルを配らないと学生がSTEP 07から先に進めなかった（issue #193）。STEP 02のタイトル画像と同じく、ダウンロードボタンにはしない。教科書をファイルとして開いていると（file://）download の指定が無視され、ブラウザにソースが表示されるだけで保存されないためである。学生は教材のフォルダをすでに「書類」へ展開しているので、そこを開いてコピーさせるほうが確実で、手順もSTEP 02の画像と同じ形（コピー→貼り付け→Copyダイアログ）になる。同梱した docs/bill-splitter/downloads/BillSplitter.java が完成プロジェクトのソースとバイト単位で一致することは python3 scripts/check-teaching-materials.py が検査するので、二重管理でずれる心配はない。STEP 07に入る前に、教材のフォルダを「書類」へ移動できているか確認する。フォルダ名の日付は配った回で変わるので、教科書には日付を書いていない。「今日はこの日付のものを使います」と口頭で指定する。貼り付け先を間違えると package 行が合わずエラーになるので、Copyダイアログの To directory を読ませる。
前提条件（金額1以上・2人以上）を守るのは呼び出す側の責任実務では、他人が作ったクラスをJavadocだけ読んで正しく呼ぶ場面が多い。守らないと例外でアプリが終了することを体験させる。STEP 07で「守らずに呼ぶとアプリが終了する」と予告し、STEP 08の入力チェックにつなげる。
ユーザー向けメッセージは画面側に置く計算クラスは計算だけを担当し、画面に出す文言を持たない。こうすると計算部分を他のアプリでも使い回せる。STEP 08の解説「なぜ画面側でチェックするのか」で扱う。
入力チェック2（NumberFormatException）は、画面から出せなくても残すandroid:inputType="number" と android:maxLength="9" で、入力欄には半角数字9桁（最大 999,999,999）までしか入らない。int の最大 2,147,483,647 より小さいので、Integer.parseInt は必ず成功し、「支払い金額は数字で入力してください」は学生の操作では表示されない（11桁の入力・文字・-・.・貼り付けのどれでも出ないことを、指定エミュレータで確認した。2026年9月20日）。それでも、レイアウトの制限とJavaのチェックは別のファイルにあり、片方が変わってももう片方で守れる。入力チェックの書き方として正しいので、完成コードは変えない。教科書はSTEP 08の解説とSTEP 11の一覧で「画面の操作では出ない」と明記している。学生に確かめさせるのは5つ。見せたいときは教員の画面で実演する（「3. 90分×3コマの進行」のSTEP 08）。
金額の表示は日本円に固定（Locale.JAPAN）引数なしの getCurrencyInstance() は端末の言語設定に従うため、英語(US)端末では $411.00 と小数第2位まで表示される。計算は1円単位なので表示とズレる。学生には説明しない（教材に入れてあるクラスの中の話）。質問が出たら「1円単位で計算しているので、円で表示するよう指定している」と答える。
findViewById は onCreate の冒頭にまとめるA01〜A06と同じ書き方にそろえる。リスナの中が処理だけになり、読みやすい。STEP 04①とSTEP 06②で、まとめて書く形をそのまま示す。

完成コードを説明するときの注意

var、Objects.requireNonNull、try〜catch (NumberFormatException e)、starterテンプレートをもとにした start メソッドの書き方は変えません。教科書で説明します。Objects.requireNonNull は「nullだったらその場で止める書き方」、try〜catch は「数字に変えられなかったときに受け止める」とだけ説明し、例外処理の一般論には広げません。BillSplitter に付いている @NonNull / @IntRange / @CheckResult は「Android Studioへのヒント」とだけ触れます（クラスのJavadocに同じ説明があります）。これは教材に入れてある完成クラスの例外です。学生が自分で打ち込むコードにはアノテーションを書かせません（Android Studioが自動で付けたものは、そのままにします）。

3. 90分×3コマの進行

コマ時間配分終了時の確認
1コマ目STEP 00：5分、STEP 01：15分、STEP 02：10分、STEP 03：20分、STEP 04：25分、再実行・個別支援：10分、理解確認：5分タイトル画像とレイアウトが表示され、参加者を登録できる。空のときと同じ名前のときにメッセージが出る。
2コマ目再開：5分、STEP 05：15分、STEP 06：20分、STEP 07：15分、個別支援：10分、確認：5分の見込みで、残り時間はSTEP 08の前半へ2人以上のときだけワリカン画面が開き、参加者は○人 が表示される。BillSplitter をプロジェクトに置けている。
3コマ目再開：5分、STEP 08：20分、STEP 09：10分、STEP 10：15分、STEP 11：15分、個別支援：10分入力チェック1・3のメッセージが出て、計算結果と合計が表示される。合計が入力した金額と一致することを説明できる。

STEP 05は、New → Java Class で作ってしまう誤りが起きやすい工程です。Java Classで作ると AndroidManifest.xml への登録とレイアウトが作られず、STEP 06で ActivityNotFoundException になりアプリが終了します。画面で New → Activity → Empty Views Activity を実演し、Launcher Activity のチェックを外すことも示します。作成後に <activity android:name=".BillSplitActivity" android:exported="false" /> が増えたことを全員で確かめます。

STEP 06は、A06のTest 3（配列を渡す）と同じ形だと最初に伝えます。渡す側は ArrayList、受け取るのは配列なので、toArray(new String[0]) が必要になる点だけ丁寧に扱います。start を onCreate の中に貼って赤いエラーが大量に出る誤りは、A06と同じく起きます。

STEP 08は、3つのチェックを書かせ、入力チェック1と入力チェック3を1つずつ動かして確かめさせます。入力チェック2のメッセージ「支払い金額は数字で入力してください」は、学生の操作では出せません（「2. この単元の教材方針」）。「これは出ない」と先に伝え、出そうとして止まる学生を作らないようにします。実演する場合は、教員の見本プロジェクトで activity_bill_split.xml の android:maxLength="9" を一時的に "11" に変えてRunし、12345678901（11桁）を入れて 計算実行 を押します。try がなければここでアプリが終了する、と説明できます。実演後は "9" に戻します。学生にはこの変更をさせません。

とくに入力チェック3（金額が人数より少ない）は、「なぜ1以上ではなく人数以上なのか」を考えさせる場面です。2円を3人で割ると0円の人が出ること、このチェックを通れば金額は必ず1以上になることを、順に確認します。

時間が足りない場合は、STEP 10のミニ練習を口頭の問いかけに切り替えます。STEP 10練習3（15人）は、登録に時間がかかるため、教員の画面で見せる方法でも構いません。

5. 理解確認と支援

問い期待する行動・答え
1234円を3人で割ると、なぜ411円が2人で412円が1人なのか1円より細かいお金は払えないため、411円ずつ配ってから、あまった1円を1人に足している、と答える。合計が1234円に戻ることも確かめる。
同じ金額でもう一度計算すると、412円の人が変わるのは？あまりの1円をだれが払うかは実行ごとに変えている、と答える。特定の人が損をしないようにするため。
キーの文字（"participants"）が、渡すMainActivityではなく受け取るBillSplitActivityにあるのは？値を入れる putExtra（start）と取り出す getStringArrayExtra（onCreate）がどちらもBillSplitActivityにあり、1か所にまとめられる。MainActivityは start に渡すだけでキーを知らなくてよい、と答える。A06と同じ考え方。
toArray(new String[0]) がいるのは？ためているのは ArrayList、Intentで渡すのは配列なので、形を変えている、と答える。
入力チェックを BillSplitter ではなく画面側に書いたのは？計算クラスは画面に出す文言を持たない。ユーザーの入力ミスは画面側で止める、と答える。
入力チェック3が「1以上」ではなく「人数以上」なのは？金額が人数より少ないと支払額が0円の人が出るため。人数は2人以上なので、このチェックを通れば金額は必ず1以上になる、と答える。
parseInt を try で囲むのは？数字に変えられないときに例外が出てアプリが終了するため、受け止めてメッセージを出す、と答える。
「支払い金額は数字で入力してください」を、画面の操作で出せないのは？入力欄が inputType="number" と maxLength="9" で半角数字9桁までにしぼられていて、9桁の数は必ず int に入るため、と答える。それでも try を書くのは、レイアウトが変わってもJava側で守れるようにするため、まで言えればなおよい。
A06で学んだ「配列を渡す」は、どこで使った？MainActivityの「ワリカン画面へ」で、参加者名の配列を BillSplitActivity.start に渡すところ。受け取りは onCreate の getStringArrayExtra、と示す。
計算結果の最後に合計の行があるのは？表示された支払額を足すと入力した金額に戻ることを、その場で確かめられるため（検算）、と答える。

エラー時は「STEP番号・ファイル・最初の赤い行・操作順」を聞きます。この単元のLogcat検索は package:jp.ac.jec.a07billsplitter level:ERROR です（共通資料：Logcat）。

よくある原因は、①BillSplitter.java をパッケージの外に置いた（package 行が合わない）、②BillSplitActivity をNew → Java Classで作った（ActivityNotFoundException）、③start を onCreate の中に貼った、④STEP 09の2行を return; の上に書いた（計算されない）、⑤一覧を append ではなく setText にした（1人分しか出ない）、の5つです。②でLauncher Activityにチェックを入れて作った場合は、<intent-filter> を消して android:exported="false" にさせます。

名前の入力中に、Androidの入力候補が「登録」ボタンに重なって押せないことがあります（android:inputType="textPersonName" のため）。候補以外の場所を一度タップしてから押すよう伝えます。教科書の「困ったとき」にも記載しています。
