教員用ガイド
ScreenTransitionSample

2つ目の画面の追加、Intentによる画面の切り替え、putExtraと既定値、キーの定数、startメソッドとオーバーロード、配列の受け渡しを、学生がLogcatで確かめながら積み上げる進行案です。90分×2コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/screen-transition-sample/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A06ScreenTransitionSample、パッケージは jp.ac.jec.a06screentransitionsample です。
  • アプリの実行にインターネット接続は不要です。画像などの追加の配布物もありません。STEP 3では、New → Activity → Empty Views Activity で2つ目の画面（TestActivity）を作ります。
  • 完成版は Documents/Android1/samples/A06ScreenTransitionSample に置きます。見本と学生のアプリは同じパッケージ名のため、端末上では同じアプリを上書きします。Run前にウィンドウの保存先を確認させます。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a を縦向きで使います（教材の確認はAndroid 17 / API 37）。
  • 受け取った値は画面に出さず、Logcatで見ます。授業前に、教員の画面でLogcatの検索欄を package:jp.ac.jec.a06screentransitionsample tag:TestActivity level:DEBUG にして見せられるようにしておきます。
  • 教員用の途中コードは teacher/screen-transition-sample/code にあります。現在のSTEPの照合に使います。STEP 4のMainActivity.javaとSTEP 5〜8のTestActivity.javaは、教科書の各STEPにある照合用の全体コードと同じ内容です。そのほかのファイルは学生には配布しません。

今回の仕様上の制約

TestActivityは画面に何も置かず、受け取った値を Log.d でLogcatに出すだけです。完成版では、どのボタンで開いても3行が出て、送っていない値は既定値か null になります。Test 1はIntentに値を入れないため、すべて既定値か null です。TestActivityから戻る処理のコードはなく、Androidの標準の戻る操作でMainActivityに戻ります。各単元では画面回転時のデータ保持と横画面のレイアウトを扱いません。考え方と対処法は共通資料：開発TipsのC章に掲載しています。

2. この単元の教材方針

方針理由授業での扱い
渡す型は int・String（スカラー2種）と String[]（配列1種）だけに絞り、long などの型・配列、ArrayList、Person（Serializable）は扱わない型のバリエーションを並べても理解は増えず読む量だけが増える（README「単元の範囲の決め方」基準3「網羅を目的にしない」）。int で仕組みを理解すれば、ほかの型も同じ形で取り出せる。String[] を残したのは、後続のA07 BillSplitterが同じ形（BillSplitActivity.start(context, String[] participants)）を使うため（「判断に迷ったとき」の基準）。ArrayList と Person（Serializable）は、後続単元でIntent経由の受け渡しに使っていないため外した。STEP 5で「ほかの型も同じ形で取り出せます」と一言添えるにとどめる。Serializable と ArrayList は教材に出てこない。
画面遷移は遷移先（TestActivity）が持つ static start(Context ...) に統一する。ただしSTEP 4だけは new Intent(...) と startActivity(...) を直接書かせる遷移先がEXTRAキーを持てるため、呼び出す側はキー名を打ち間違えられず、あとでEXTRAを足すときも呼び出し側を直さずに済む。A07 BillSplitterも同じ start の形で統一されているため、先に出てくるA06から揃えた。STEP 4を例外にしたのは、2つ目の画面を初めて開く回でいちばん素の形を先に見せるためで、start ができるSTEP 6で揃え直す構成にした。STEP 6④で、STEP 4に書いたbtn1の処理を TestActivity.start(this) に置き換えさせ、不要になった import android.content.Intent; を消させる。
EXTRAキーの定数は、送るMainActivityではなく受け取るTestActivity側に置く値を入れる putExtra（start）と取り出す getXxxExtra（onCreate）がどちらもTestActivityにあるため、privateで1か所にまとめられる。MainActivityは start に値を渡すだけでキーを知らなくてよい。Android Studioのstarterテンプレートも、開かれる側のクラスに start を作る。STEP 6の解説：キーの定数をTestActivityに置く理由で、流れの図と4つの理由の表を使って説明する。
3つのボタンは findViewById(R.id.btnN).setOnClickListener(...) とその場で呼ぶだけにし、変数やフィールドに入れない全単元共通ルール（README「完成コードの書き方」）は、取得したViewをその場でリスナを付けるためだけに使い、以後参照しない場合を例外として認めている。A06の3つのボタンはそれぞれ1回しか呼ばれず onCreate の直下にあるため、ルールが防ぎたい問題（リスナの中で呼ぶ、同じidを2回取得する）が起きない。変数化すると教科書と teacher/screen-transition-sample/code の掲載コードに波及する一方、得られるのは見た目の統一だけと判断した。特別な説明はしない。STEP 2でボタンを配置したあと、STEP 4以降で各ボタンのリスナをこの形のまま扱う。

完成コードを説明するときの注意

var、starterテンプレートをもとにした start メソッド（引数の違う3つのオーバーロード）の書き方は変えません。教科書で説明します。

Intentの putExtra の説明（javadoc）と公式ガイドでは、キーの文字列の先頭にパッケージ名を付けるよう案内されています。完成コードのキー（"intValue" など）は付けていません。アプリ内の明示的なIntentでは問題なく動くため、コードは変えず、教科書でも「公式の推奨どおり」とは書いていません。キーの定数を受け取る側に置く理由は、①値を入れる putExtra（start）と取り出す getXxxExtra（onCreate）が同じTestActivityにある、②Android Studioのstarterテンプレートも開かれる側のクラスに start を作る、の2点を根拠に説明しています。

5. 理解確認と支援

問い期待する行動・答え
Test 1でintValueが0、stringValueがnullなのは？Test 1はIntentに何も入れていない。getIntExtra は2つ目の引数（既定値）を返し、getStringExtra は null を返す、と答える。
キーの定数が、送るMainActivityではなくTestActivityにあるのは？値を入れる putExtra（start）と取り出す getXxxExtra（onCreate）がどちらもTestActivityにあり、privateで1か所にまとめられる。MainActivityは start に値を渡すだけで、キーを知らなくてよい、と答える。
キーを直接書いて打ち間違えると？赤いエラーにならず、既定値が出る（STEP 8練習2）。定数の名前を打ち間違えると赤いエラーになるので気付ける、と答える。
startが3つあってもよいのは？引数の型と数が違うので、渡した値からどの start かが決まる（オーバーロード）、と答える。"2" の " " を外すと合う start がなくなり、Runの前にエラーになる（STEP 8練習3）ことも示せる。
実際によく使う渡し方は？Test 2の形で、IDなど小さな値を1つずつ渡す。自分で作ったクラスを丸ごと渡したり、大きなデータを渡したりすることは避け、IDを渡して開いた画面でデータを用意する、と答える。
戻るコードがないのに戻れるのは？開いた画面は前の画面の上に重なり、戻る操作で上の画面が閉じて、下のMainActivityがまた見える、と答える。
回転したら？この単元では画面回転時のデータ保持を扱わない、と理解している。なお、回転でTestActivityが作り直されても getIntent() は同じIntentを返すため、同じ3行がもう一度Logcatに出る。押し直しと見分けがつかない場合は、Logcatの時刻を見るよう伝える。

エラー時は「STEP番号・ファイル・最初の赤い行・操作順」を聞きます。A06のLogcat検索は、エラーが package:jp.ac.jec.a06screentransitionsample level:ERROR、受け取った値が package:jp.ac.jec.a06screentransitionsample tag:TestActivity level:DEBUG です。tag:TestActivity はTestActivityを含むタグも表示するため、VRI[TestActivity] の行が混ざることがあります。読み飛ばしてよいと伝えます。

よくある原因は、TestActivityをNew → Java Classで作った（Manifestに登録がなく ActivityNotFoundException）、start をonCreateの中に貼った、定数をコピーしたあとに putExtra と getXxxExtra のキーを取り違えた（エラーにならず既定値になる）、Logcatの検索欄が tag:MainActivity のまま、の4つです。Launcher Activityにチェックを入れて作った場合は、STEP 3の照合用Manifestと見比べ、TestActivityの <activity> から <intent-filter> を消し、exportedを false にさせます（この場合にどちらの画面から起動するかは確認していません）。
