ScreenTransitionSample

2つ目の画面の追加、Intentによる画面の切り替え、putExtraと既定値、キーの定数、startメソッドとオーバーロード、配列・ArrayList・自分で作ったクラスの受け渡しを、学生がLogcatで確かめながら積み上げる進行案です。90分×2コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/screen-transition-sample/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A06ScreenTransitionSample、パッケージは jp.ac.jec.a06screentransitionsample です。
  • アプリの実行にインターネット接続は不要です。画像などの追加の配布物もありません。STEP 3では、New → Activity → Empty Views Activity で2つ目の画面（TestActivity）を作ります。
  • 完成版は Documents/Android1/samples/A06ScreenTransitionSample に置きます。見本と学生のアプリは同じパッケージ名のため、端末上では同じアプリを上書きします。Run前にウィンドウの保存先を確認させます。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a を縦向きで使います（教材の確認はAndroid 17 / API 37）。
  • 受け取った値は画面に出さず、Logcatで見ます。授業前に、教員の画面でLogcatの検索欄を package:jp.ac.jec.a06screentransitionsample tag:TestActivity level:DEBUG にして見せられるようにしておきます。
  • 教員用の途中コードは teacher/screen-transition-sample/code にあります。現在のSTEPの照合に使います。STEP 4のMainActivity.javaとSTEP 5〜8のTestActivity.javaは、教科書の各STEPにある照合用の全体コードと同じ内容です。そのほかのファイルは学生には配布しません。

今回の仕様上の制約

TestActivityは画面に何も置かず、受け取った値を Log.d でLogcatに出すだけです。完成版では、どのボタンで開いても17行が出て、送っていない値は既定値か null になります。Test 1はIntentに値を入れないため、すべて既定値か null です。charの既定値は半角スペースなので、charValue: のあとは空白に見えます。TestActivityから戻る処理のコードはなく、Androidの標準の戻る操作でMainActivityに戻ります。各単元では画面回転時のデータ保持と横画面のレイアウトを扱いません。この観点は別単元の演習アプリで検証します。

完成コードを説明するときの注意

var、starterテンプレートをもとにした start メソッド（引数の違う4つのオーバーロード）、Serializable、IntentCompat の書き方は変えません。教科書で説明します。Serializable は「Intentに入れて渡せる形にする印」、toString は「文字につなげたときの文字を決めるメソッド」とだけ説明し、深掘りしません。Personの getName と getAge は、このアプリのどこからも呼ばれていません。教科書では「今回のアプリでは使っていない」と明記しています。

Intentの putExtra の説明（javadoc）と公式ガイドでは、キーの文字列の先頭にパッケージ名を付けるよう案内されています。完成コードのキー（"intValue" など）は付けていません。アプリ内の明示的なIntentでは問題なく動くため、コードは変えず、教科書でも「公式の推奨どおり」とは書いていません。キーの定数を受け取る側に置く理由は、①値を入れる putExtra（start）と取り出す getXxxExtra（onCreate）が同じTestActivityにある、②Android Studioのstarterテンプレートも開かれる側のクラスに start を作る、の2点を根拠に説明しています。

4. 理解確認と支援

問い期待する行動・答え
Test 1でintValueが0、stringValueがnullなのは？Test 1はIntentに何も入れていない。getIntExtra は2つ目の引数（既定値）を返し、getStringExtra は null を返す、と答える。
キーの定数が、送るMainActivityではなくTestActivityにあるのは？値を入れる putExtra（start）と取り出す getXxxExtra（onCreate）がどちらもTestActivityにあり、privateで1か所にまとめられる。MainActivityは start に値を渡すだけで、キーを知らなくてよい、と答える。
キーを直接書いて打ち間違えると？赤いエラーにならず、既定値が出る（STEP 10練習2）。定数の名前を打ち間違えると赤いエラーになるので気付ける、と答える。
startが4つあってもよいのは？引数の型と数が違うので、渡した値からどの start かが決まる（オーバーロード）、と答える。3.0f の f を消すと合う start がなくなり、Runの前にエラーになる（STEP 10練習3）ことも示せる。
new ArrayList<>(List.of(…)) にするのは？putIntegerArrayListExtra と start がArrayListを受け取るため、と答える。
PersonにSerializableがないと？putExtra と IntentCompat.getSerializableExtra の行がエラーになる。「Intentで渡せる形にする印」と答えれば十分。
実際によく使う渡し方は？Test 2の形で、IDなど小さな値を1つずつ渡す。自分で作ったクラスを丸ごと渡したり、大きなデータを渡したりすることは避け、IDを渡して開いた画面でデータを用意する、と答える。
戻るコードがないのに戻れるのは？開いた画面は前の画面の上に重なり、戻る操作で上の画面が閉じて、下のMainActivityがまた見える、と答える。
回転したら？この単元では画面回転時のデータ保持を扱わない、と理解している。なお、回転でTestActivityが作り直されても getIntent() は同じIntentを返すため、同じ17行がもう一度Logcatに出る。押し直しと見分けがつかない場合は、Logcatの時刻を見るよう伝える。

エラー時は「STEP番号・ファイル・最初の赤い行・操作順」を聞きます。A06のLogcat検索は、エラーが package:jp.ac.jec.a06screentransitionsample level:ERROR、受け取った値が package:jp.ac.jec.a06screentransitionsample tag:TestActivity level:DEBUG です。tag:TestActivity はTestActivityを含むタグも表示するため、VRI[TestActivity] の行が混ざることがあります。読み飛ばしてよいと伝えます。

よくある原因は、TestActivityをNew → Java Classで作った（Manifestに登録がなく ActivityNotFoundException）、start をonCreateの中に貼った、Person.javaより先に start を書いて android.app.Person や androidx.core.app.Person をimportした、定数をコピーしたあとに putExtra と getXxxExtra のキーを取り違えた（エラーにならず既定値になる）、Logcatの検索欄が tag:MainActivity のまま、の5つです。Launcher Activityにチェックを入れて作った場合は、STEP 3の照合用Manifestと見比べ、TestActivityの <activity> から <intent-filter> を消し、exportedを false にさせます（この場合にどちらの画面から起動するかは確認していません）。charValue: のあとに何も出ないのは、Test 1・3・4・5では正常です。

5. STEP 5・9の背景：charの既定値とIntentCompat

教材を作るときに、完成コードを次のように直しました（PR #18のレビュー対応、2b014bf）。教科書はこの直したあとのコードに合わせています。

  • 受け取り：以前は getIntent().getSerializableExtra(EXTRA_KEY_PERSON) でした。Intent#getSerializableExtra(String) はAndroid 13（API 33）から非推奨です（SDKのIntent.javaの @deprecated、api-versions.xmlの deprecated="33"）。型を指定する getSerializableExtra(String, Class) はAPI 33からのため、minSdk 31のこのプロジェクトでは直接呼べません。そこで、androidx.core 1.18.0の IntentCompat.getSerializableExtra(Intent, String, Class<T>) に変えました。API 34以上では新しいメソッドを呼び、33以下では取り出したあとに型を確かめます。キーがないときや型が違うときは null を返します。androidx.coreはappcompat経由で入っているため、build.gradle.ktsは変えていません。
  • charの既定値：以前の '0' は、Test 1でcharValueに0と出て、値を受け取れたように見えるため、' '（半角スペース）に変えました。'\0' はLogcatで文字化けするため採用していません。
  • 同じPRで、プロジェクト名とパッケージをA01〜A05と同じ2桁の A06ScreenTransitionSample / jp.ac.jec.a06screentransitionsample にそろえました（33605db）。

教科書STEP 9では、IntentCompatを「3つ目の Person.class でPersonとして受け取りたいと伝える」「以前の書き方はAndroid 13から非推奨なので、古いAndroidでも新しいAndroidでも同じ書き方で使えるクラスを使う」の2点だけ説明しています。ひな形の ViewCompat と同じく、名前にCompatが付くクラスとして紹介しています。

参照：IntentCompat、Intent、Intents and intent filters、Parcelables and bundles（Android公式）。
