教員用ガイド
MemoApp

A08で学んだ SharedPreferences を、毎日使えるアプリの形にする単元です。新出概念は TextView.append だけで、残りはA07とA08の組み合わせ。90分×1コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/memo-app/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A09MemoApp、パッケージは jp.ac.jec.a09memoapp です。
  • 配布物が1つあります。STEP 02で使う title_memo.png です。完成プロジェクトZIPの app/src/main/res/drawable/title_memo.png がそのまま使えます。授業前に配布できる場所へ置きます。
  • 完成版は Documents/Android1/samples/A09MemoApp に置きます。見本と学生のアプリは同じパッケージ名のため、端末上では同じアプリを上書きします。保存したメモも共有されます。見本でメモを追加したあとに学生のアプリをRunすると、学生側の初回起動でメモが入った状態になります。STEP 03の「一覧が空」を見せる前に、学生の端末で一度データ削除させるか、アプリのデータを消去させてください。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a を縦向きで使います。
  • アプリの実行にインターネット接続は不要です。この単元ではLogcatを使いません。

今回の仕様上の制約

1件だけの削除はできません（clear() による全削除のみ）。1件削除は RecyclerView が必要で、README 基本方針7によりAndroidプログラミング1では扱いません。学生から必ず質問が出るので、STEP 00で先回りして「Androidプログラミング2で扱う」と伝えてください。画面回転時のデータ保持と横画面のレイアウトも扱いません（共通資料：開発TipsのC章に掲載しています）。

2. この単元の教材方針

方針理由授業での扱い
メモ一覧を ArrayList ではなくTextViewの表示文字列として保存するA07で ArrayList を使ったのは重複チェックと人数チェックのため。A09には判定がなく、ArrayList にすると保存時の String.join と復元時の split が増えるだけで、学習項目も増える。「空文字を split すると要素1個の配列が返る」という初学者が確実に踏む罠も抱える。STEP 05の解説「なぜArrayListを使わないのか」でA07と表で比較する。この説明を飛ばすと「単元ごとに書き方が違う」とだけ受け取られる。
保存なし（STEP 04）→ 保存あり（STEP 05）の順で作る先に画面の中だけで動かすと、append の働きに集中できる。保存を足したときの変化（終了しても残る）が体験として際立つ。STEP 04の最後に「いま終了すると消えます」と明示し、実際に試させてからSTEP 05へ進む。
キーは private static final String にまとめるA08のSTEP 09練習3で「直書きは打ち間違えても赤いエラーにならない」を実演させている。直後の単元で直書きに戻ると方針がぶれる。STEP 05①で、A08と同じ形だと一言添える。
一覧のTextViewに layout_weight="1" を付けるlines による固定高だと、画面サイズによって余白が大きく残ったり足りなくなったりする。メモの増減でボタンの位置が動かない利点もある。STEP 03の表で理由を短く扱う。
「データ削除」で保存と画面の両方を消す片方だけ消すと、画面には残るが再起動すると消えている、という分かりにくい状態になる。保存と表示が別物だと気づかせる良い教材。STEP 06の解説とSTEP 07練習3で扱う。

完成コードを説明するときの注意

var、ラムダ式、findViewById の明示キャスト、Snackbar の書き方は変えません。単元をまたいで同じ形にそろえるためです（READMEの「完成コードの書き方（全単元共通）」）。

3. 90分×1コマの進行

時間配分終了時の確認
STEP 00：5分、STEP 01：10分、STEP 02：10分、STEP 03：15分、STEP 04：20分、STEP 05：15分、STEP 06：5分、STEP 07：10分メモを追加でき、アプリを終了して開き直しても残る。データ削除で一覧と保存の両方が消える。

STEP 04が最も時間を使います。append と setText の違い、return; の役割、+ "\n" の3点でつまずきが出ます。STEP 07の練習1・2はこの3点の確認になっているので、時間が足りないときはSTEP 04の説明を短くして練習に回すほうが定着します。

STEP 05は、var prefs = ... をボタンの処理より上に書く必要があります。下に書くとリスナの中から見えず赤いエラーになります。板書か画面で位置を示してください。

時間が余ったら、STEP 07のふり返り5問を口頭で回すか、練習3（データ削除から setText("") を消す）まで試させます。

5. 理解確認と支援

問い期待する行動・答え
append と setText の違いはappend は後ろに足す、setText は置き換える、と答える。setText にすると1件しか残らないことを説明できる。
空のときの return; を消すとどうなるかメッセージが出たあとも処理が続き、空のメモが追加されてしまう、と答える。
+ "\n" は何のためにあるか改行。ないとメモが全部つながって1行になる、と答える。
アプリを終了してもメモが残るのはなぜかedit.putString と edit.apply() でファイルに保存しているため。起動時に prefs.getString で読み直している、と答える。
A07では ArrayList を使ったのに、A09で使わないのはなぜかA07は重複チェックと人数チェックに必要だったが、A09には判定がないため、と答える。「判定が必要になったらデータを別に持つ」と言えれば十分。
「データ削除」で2つのものを消しているのはなぜか保存（ファイル）と画面の表示は別物だから、と答える。clear() はファイルしか消さない。
保存されているのは何か画面に表示している文字列まるごと1つ。改行も含めて1つの値として保存している、と答える。

エラー時は「STEP番号・ファイル・最初の赤い行・操作順」を聞きます。この単元のパッケージは jp.ac.jec.a09memoapp です。アプリが終了してしまうときだけ 共通資料：Logcat を開き、package:jp.ac.jec.a09memoapp level:ERROR で確認します。

よくある原因は、①append を setText にした（1件しか出ない）、②+ "\n" を忘れた（全部つながる）、③var prefs = ... をリスナより下に書いた（赤いエラー）、④edit.apply() を書き忘れた（終了すると消える）、⑤データ削除で txtMemoList.setText("") を書き忘れた（画面が消えない）、の5つです。

③は「prefs が赤い」という形で出ます。学生は原因をコードの中身に求めがちなので、行の順番を最初に確認させてください。

名前の入力中に、Androidの入力候補やキーボードがボタンに重なって押せないことがあります。キーボードを閉じてから押すよう伝えます。理由と対処は共通資料：開発TipsのB章にあります。
