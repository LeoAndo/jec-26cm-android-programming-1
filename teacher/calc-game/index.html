教員用ガイド
CalcGame

タイマー、フィールド、乱数、配列、採点を、学生が動作確認しながら積み上げる進行案です。90分×3コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/calc-game/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A02CalcGame です。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a を縦向きで使います。横向きでは画面下部が隠れるため、今回の保証範囲に含めません。
  • 完成版は Documents/Android1/samples/A02CalcGame に置きます。学生の作成先と混同しないよう、Run前に保存先を確認します。
  • 教員用の途中コードは teacher/calc-game/code にあります。学生には配布せず、現在のSTEPの照合に使います。

今回の仕様上の制約

STOP後のSTARTは、現在の問題・問題番号・正解数を保ったままタイマーだけを再開します。各単元では画面回転時のデータ保持を扱いません。回転などでActivityが再生成された場合はゲームをやり直します。考え方と対処法は共通資料：開発TipsのC章に掲載しています。

2. この単元の教材方針

方針理由授業での扱い
画面の部品のうち txtMessage だけフィールドにし、ほかの部品は var のローカル変数にするtxtMessage は onCreate のほかに、STEP 6で作る startQuestion() からも使う。以前は startQuestion() の中でもう一度 findViewById していた（同じidの二重取得）ので、フィールドに変えた（PR #25）。onCreate 以外のメソッドからも使うViewはフィールドにし、同じidに対して findViewById を2回呼ばない（READMEの「完成コードの書き方」Viewの取得2。A04WebViewAppの webView と同じ形）。STEP 4が「状態を覚えるフィールド」の回なので、①で値のフィールド5つと一緒に追加する。「STEP 6で作る別のメソッドからも使うため、フィールドにする」と説明する。②では、txtMessage の行だけ var が付かない理由を説明する。
操作ボタン3つ（START / STOP / RESET）は、findViewById の結果をキャストしない。Chronometer と TextView はキャストする操作ボタンで使うのは、Viewが持つクリック登録と、有効・無効の切り替えだけのため。Chronometer と TextView は、それぞれの部品の機能を使うのでキャストする。STEP 4②の説明で扱う。数字ボタンは表示文字を読むので、STEP 7で (Button) にキャストする。A01ではボタンも (Button) でキャストしていたので、書き方の違いを聞かれたら、この説明で答える。
ゲーム中かどうかは、isPlaying フィールドで自分で覚えるChronometer が動いているかどうかのフラグ（mStarted）は、外から取得できないため。完成コードのフィールドのコメントに、この理由を残している。STEP 4①のコードに、このコメントが入っている。表では「回答を受け付けるか」とだけ説明し、mStarted には触れていない。コメントについて質問が出たら、「Chronometerに動いているかを聞く方法がないので、自分で覚えている」と答える。
STEP 5のSTARTの処理には startQuestion() の呼び出しを入れない。STEP 6でメソッドを作ったあとに足す以前はSTEP 5のコードに呼び出しがあった。メソッドを作るのはSTEP 6なので、STEP 5の時点ではコンパイルが通らず、「Runで確かめる」で学生全員が赤いエラーに当たっていた（issue #66）。呼び出しをSTEP 6へ移しても、STEP 5「START / STOP / RESET」、STEP 6「メソッドにして呼び出す」という各回の主題は保てる。STEP 5の注記「ここではタイマーだけ」で、問題文はまだ出ないと伝える。STEP 6②で、isPlaying = true; の直前に4行を追加させる。照合コード（STEP 5・STEP 6）の確認ポイントにも入れている。
STOPのあとのSTARTでは、問題を作り直さない（if (answer == 0) のときだけ startQuestion() を呼ぶ）最初の実装は、STARTのたびに startQuestion() を呼んでいた。これだと、STOP → STARTで未回答の問題が別の問題に置き換わる。問題番号と正解数は保たれるので、答えずに問題だけを引き直せてしまう。PR #3 のレビューでこの指摘を受けて直した。STEP 6②の説明と、注記「STOPからの再開について」で扱う。「5. 理解確認と支援」の最初の問いでも確かめる。
乱数は ThreadLocalRandom で作る。RandomGenerator は使わないRandomGenerator はAPI Level 35から使える。この授業のMinimum SDKはAPI 31で、OSバージョンで処理を分ける書き方は使わないため。完成コードの startQuestion() に、コメントアウトした行とこの理由を残している。STEP 6①のコードに、コメントアウトした RandomGenerator の行がそのまま入っている。教科書の本文では触れていない。質問が出たら、コメントのとおりに答える。
数字ボタン9個は、idの配列と拡張for文で取得し、同じクリック処理を登録する9個のボタンに同じ処理を付けるため。ループでidを引いて取得するこの形は、findViewById を onCreate の冒頭にまとめるルールの例外として認めている（READMEの「完成コードの書き方」Viewの取得4）。STEP 7で配列と拡張for文を説明する。for文は画面を作るときに実行され、中のクリック処理はボタンを押したときに実行されることも伝える。「5. 理解確認と支援」に問いがある。

画面回転時のデータ保持と横画面のレイアウトを扱わない方針（README 基本方針14）は、「1. 授業前の準備」に書いています。

完成コードを説明するときの注意

var、ラムダ式、findViewById の書き方（操作ボタンだけキャストしない点を含む）は変えません。単元をまたいで同じ形にそろえるためです（READMEの「完成コードの書き方（全単元共通）」）。完成コードに残っているコメントも、そのままにします。

5. 理解確認と支援

問い期待する行動・答え
STOP後にSTARTすると問題が変わらないのはなぜ？START処理の if (answer == 0) を示し、answerが残っていると出題しないと説明する。
なぜ数字ボタンを配列にした？9個に同じリスナーをfor文で登録するため、と答える。

6. 到達度

  • 学生自身がSTARTから10問回答し、結果を表示できる。
  • 正解数・問題番号・経過時間のフィールドを1つずつ指させる。
  • STOP/STARTで現問題を維持し、RESETで初期状態へ戻ることを実演できる。
  • STEP 10の変更を試したあと、完成版の値に戻してRunする。

7. 教材の保守と確認

  • 完成コードを変更したら、教科書の部分コード、完成コード、teacher/calc-game/code、画像、練習の答えをまとめて確認し、python3 scripts/package-hello-android.py --project A02CalcGame --output docs/calc-game/downloads/A02CalcGame.zip で配布用ZIPを再作成します。教科書のコードと完成プロジェクトの一致は python3 scripts/check-teaching-materials.py で確かめます。
  • アプリ画像5枚のうち、app-initial（起動直後。問題文は空欄でSTARTのみ有効）はSTEP 00とSTEP 03の確認の2箇所、app-playing（ゲーム中。1問目の式が出てSTOPのみ有効）はSTEP 00とSTEP 06の確認の2箇所で使っています（表示が同じため）。app-paused（STOP後。時間と問題を保持しSTART/RESETが有効）はSTEP 06、app-result（結果表示。正解数と時間は例でプレイごとに変わります）とapp-snackbar（終了後に数字ボタンを押すと出る「ゲーム中のみボタンを押せます」の案内）はSTEP 09で使っています。撮影に使ったエミュレータ・Android/APIバージョン・撮影日は、本PRでは確認できていません。
  • 新規プロジェクト作成の3画像（new-project、empty-views-activity、project-settings）は教員提供資料を使用しています。
  • 各STEPの照合コードは、完成プロジェクトのコピーにそのSTEPまでのファイルを入れ、STEP 01〜09のすべてで assembleDebug が通ることを確認しました（2026年9月19日）。完成コードを変更したら、照合コードも合わせて更新します。
  • 印刷時は補足・解答も展開されます。解答を配布したくない場合は、ブラウザで授業中に開く方式を使ってください。
