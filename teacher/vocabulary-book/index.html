教員用ガイド
VocabularyBook

A10で学んだRoomを、2つの画面で共有する単元です。新出概念は LiveData だけ。Androidプログラミング1の最終単元です。90分×1コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/vocabulary-book/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A11VocabularyBook、パッケージは jp.ac.jec.a11vocabularybook です。
  • 配布物はありません。STEP 02で使う logoeng.png は教材のフォルダに同梱してあり（実体は docs/vocabulary-book/downloads/logoeng.png）、学生がFinderでコピーします。手順は、書類の教材フォルダ（android1-student-materials- ＋日付）から docs → vocabulary-book → downloads を開き、Android Studioの app/src/main/res/drawable に貼り付ける形です。STEP 01の前に、教材のフォルダを「書類」へ移動できているか確認させます（共通資料：はじめの準備の1.）。
  • 完成版は、配布する教材のフォルダの samples/A11VocabularyBook に、展開済みで入っています。学生はダウンロードも展開もせず、Android Studioの Open で選ぶだけで開けます。見本と学生のアプリは同じパッケージ名のため、端末上では同じアプリを上書きします。登録した単語も共有されます。STEP 05の「一覧が空から始まる」を見せる前に、学生の端末でアプリのデータを消去させてください。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a を縦向きで使います。
  • STEP 02のSyncにネット接続が必要です（A10と同じ）。アプリの実行には不要です。この単元ではLogcatを使いません。

今回の仕様上の制約

登録した単語の削除・書き換えはできません。カードの並べ替えやランダム出題もありません。一覧は TextView に並べただけで、行をタップして選ぶこともできません（RecyclerView はREADME 基本方針7によりAndroidプログラミング1では扱いません）。画面回転で見ていたカードは1問目に戻ります（共通資料：開発TipsのC章）。登録した単語は画面を回しても消えません。

2. この単元の教材方針

README「単元の範囲の決め方（全単元共通）」に沿って、新概念を LiveData 1つに絞っています。

方針理由授業での扱い
allowMainThreadQueries() を残し、別スレッドは扱わないA10で「別スレッドを意識しない構成」にした方針を最終単元まで通す。スレッドを入れると、この単元の新概念が LiveData とワーカースレッドの2つになり、基準1を超える。質問が出たら「実務では別スレッドで行う。Androidプログラミング2以降で扱う」とだけ答える。
単語追加画面に「登録ずみの単語」を置くLiveData の利点は、画面上の変化として見せないと伝わらない（基準2）。追加した瞬間に一覧が変わり、しかもコードに setText を書いていない、という対比が要る。STEP 05の解説と、STEP 07の練習1（observe の中を消す）で扱う。この対比を飛ばすと「なぜ LiveData なのか」が残らない。
画面を開く処理を start(Context) に寄せるA07 BillSplitActivity.start(...) と同じ形。開かれる側が自分の開き方を持つので、あとでEXTRAを足すときも呼び出し側を直さずに済む。STEP 05③で、start の各行の意味を表で確認する（A07 STEP 06①の表と同じ文面）。A07と同じ形だと一言添える。
btn_back / btn_next を enabled="false" から始めるLiveData はあとからデータを届ける。届く前に押せると空のリストに触れて落ちる。非同期に届くという性質が、そのままUIの初期状態に効く例。STEP 06①で理由を短く扱う。練習3で実際に落としてみせる。
CardActivity の6つのViewをフィールドにするupdateCardView() は「次へ」「戻る」とLiveDataの通知のたびに呼ばれる。ここで findViewById を呼ぶと、同じidを何度も探し直すことになる（READMEの「Viewの取得」2）。A02CalcGameの txtMessage と同じ直し方。STEP 06②で「onCreate の外からも使うViewはフィールド」とA02を振り返る。フィールドが6つに増えるので、役割は表でまとめて読ませる。
タイトル画像は別に配布せず、教材のフォルダからFinderでコピーさせる。ダウンロードボタンにはしない以前は「先生から配られる」とだけ書いてあり、教員が別にファイルを配らないと学生が先に進めなかった。そこで同じ画像を docs/vocabulary-book/downloads/ に置き、教科書のボタンからダウンロードさせた（issue #123）。ところが、教科書をファイルとして開いていると（file://）、ブラウザは download の指定を無視するので、ボタンを押しても保存されず、画像がブラウザに表示されるだけだった。学生は教材のフォルダをすでに「書類」へ展開しているので、そこを開いてコピーさせるほうが確実で、ブラウザの種類にも左右されない（issue #192）。置いた画像が完成プロジェクトの画像とバイト単位で一致することと、教科書のSTEP 02に置き場所とファイル名が書いてあることを python3 scripts/check-teaching-materials.py が検査するので、二重管理でずれる心配はない。完成プロジェクトの画像を差し替えたら、cp A11VocabularyBook/app/src/main/res/drawable/logoeng.png docs/vocabulary-book/downloads/ で置き直す。STEP 02に入る前に、教材のフォルダを「書類」へ移動できているか確認する。フォルダ名の日付は配った回で変わるので、教科書には日付を書いていない。「今日はこの日付のものを使います」と口頭で指定する。downloads には完成プロジェクトのZIPも入っているが、STEP 02では選ばせない。Copyダイアログの画像（drawable-copy.png）は撮り直していない。Copy file のうしろに写っているコピー元は先生の保存先で、学生の画面では教材のフォルダの中の場所が出る。確認させるのは New name と To directory で、どちらもコピー元には左右されない。
Roomの準備と3つのファイルは、A10を開かなくても進められるように書く学生は過去の単元を読み返さない（README「授業用教科書の基本方針」7）。STEP 02の追記する3行と [plugins] の確かめ方、STEP 03の New → Java Class の手順、アノテーションの意味は、A11の中に書く。ただし新概念は LiveData 1つのままにするため、意味は表の1行ずつにとどめる。A10の解説（@Upsert だけにした理由、シングルトンの説明）と、クラス作成のスクリーンショットは持ってこない。STEP 02・03は「A10でもやった」と声をかけてよいが、A10の教科書は開かせない。時間をかけるのはSTEP 03②の LiveData の行。
重複チェックは =（LIKE ではない）LIKE は % と _ をワイルドカードとして扱うため、ちがう単語に誤ヒットする。STEP 03②の注意書きで扱う。
三項演算子（isVisible ? A : B）と、ボタン付きのSnackbar（LENGTH_INDEFINITE・setAction）は、完成コードを書き換えずに教科書の表で説明する。新概念には数えないどちらも、全単元のうちA11の CardActivity.java にしか出てこない（git grep で確認ずみ）。READMEの基準1を字面どおりに読めば「それまでに1度も出ていないAPI」に当たる。それでも数えないのは、新しい考え方が増えないため。三項演算子はA02から使っている if / else の別の書き方で、LENGTH_INDEFINITE と setAction はA01から使っている Snackbar の設定。どちらも画面で体感させる主題（基準2）ではなく、説明が1度もないまま残すほうが学生は読めない。if / else への書き換えは、完成コードはオーナーの書き方を保つ方針（AGENTS.md §11）により行わない。STEP 06②の表の1行ずつを読ませる。解説の節や練習は足さない。時間をかけるのは LiveData のまま。質問が出たら、同じ処理を if / else で板書して見比べさせる。

方針の例外：@NonNull を学生に書かせます

A10と同じ扱いです。@Entity のフィールドに付けた @NonNull は「この列は NOT NULL」という表の定義そのもので、外すと表の形が変わります。ほかの単元では「@NonNull は自分で書かない」ので、理由なしに出てくると矛盾して見えます。A11の教科書でも、STEP 03①の注意書きに理由を書いています。「A10と同じ」で済ませず、そこを読ませてください。

完成コードを説明するときの注意

var、ラムダ式、findViewById の明示キャスト、Snackbar の書き方は変えません（READMEの「完成コードの書き方（全単元共通）」）。

3. 90分×1コマの進行

時間配分終了時の確認
STEP 00：5分、STEP 01：10分、STEP 02：10分、STEP 03：15分、STEP 04：10分、STEP 05：20分、STEP 06：15分、STEP 07：15分3つの画面がつながり、追加した単語がカードに出る。同じ英単語は登録できない。

STEP 05が山場です。Activityの追加（New → Activity）、LiveDataの observe、重複チェックの3つが同時に出ます。New → Java Class で作って AndroidManifest.xml に登録されず、ボタンを押した瞬間にアプリが終了する事故が毎回起きます。A06・A07で同じ注意をしていますが、ここでも机間指導で作り方を確認してください。

STEP 04でボタンを「まだ何もしない」状態にしているのは意図的です。先にメニュー画面を出しておくと、STEP 05・06で画面が増えるたびにRunして確かめられます。各STEPの終わりで必ずビルドが通る順番にしてあります。

STEP 07の15分は、完成チェックの表（8行）と保存までの時間です。練習1〜3は含めていません。この表は、アプリを消したところから始めて、単語を2件（日本語入力あり）追加し、3つの画面を行き来して、アプリを終了して開き直すまでを確かめます。操作だけで5分では終わりません。STEPの合計は100分になり、90分には収まりません。90分で終える回は、完成チェックの表までを全員に行わせ、練習は時間が余ったときに回してください。

時間が余ったら、STEP 07の練習1〜3を回します。練習1（observe の中を消す）と練習2（clear() を消す）は、この単元の要点そのものです。STEP 06の解説を短くしてでも、この2つは試させるほうが定着します。

6. 理解確認と支援

問い期待する行動・答え
LiveData<List<Item>> と List<Item> の違いはList はそのときの中身を1回受け取るだけ。LiveData は中身が変わるたびに知らせてくれる、と答える。
単語を追加したあと、一覧を出し直す処理を書かなくてよいのはなぜかobserve でLiveDataを見張っているため。追加すると observe の中がもう一度呼ばれる、と答える。A10では setText を自分で書いていたことと対比できる。
cardList.clear() を消すとどうなるかLiveDataは変わるたびに呼ばれるので、そのたびに同じ単語が積み上がる。全3問が全6問になる、と答える。
「前へ」「次へ」を最初は押せない状態にしているのはなぜかLiveDataはあとからデータを届けるため。届く前に押すと、空のリストに触れて落ちる、と答える。
画面を開く処理を、開かれる側の start に書いているのはなぜか開かれる側が自分の開き方を持つほうが、渡す値が増えたときに呼び出し側を直さずに済む、と答える。A07の BillSplitActivity.start(...) と同じ形だと気づければ十分。
重複チェックが = で LIKE ではないのはなぜかLIKE は % や _ を特別な文字として扱うため、ちがう単語に当たってしまう、と答える。
A10とA11で、Roomの使い方が変わったところはgetAll() の戻り値が LiveData になったこと。保存したあとの setText が要らなくなったこと、と答える。

エラー時は「STEP番号・ファイル・最初の赤い行・操作順」を聞きます。この単元のパッケージは jp.ac.jec.a11vocabularybook です。アプリが終了してしまうときだけ 共通資料：Logcat を開き、package:jp.ac.jec.a11vocabularybook level:ERROR で確認します。

よくある原因は、①画面を New → Java Class で作った（AndroidManifest.xml に登録されず、ボタンを押した瞬間に終了）、②cardList.clear() がない（一覧が二重）、③XMLの enabled="false" がない（0件で「次へ」を押すと落ちる）、④getAll() の戻り値を List にした（表示が変わらない）、⑤ItemDao を Class で作った、の5つです。

①がこの単元で最も多い事故です。アプリが終了するだけでコンパイルは通るため、学生は原因をJavaのコードに求めます。まず AndroidManifest.xml を開かせて、<activity> の行があるかを確認させてください。

入力中にキーボードがボタンに重なって押せないことがあります。キーボードを閉じてから押すよう伝えます。理由と対処は共通資料：開発TipsのB章にあります。

7. 到達度

  • 3つの画面を行き来できる。
  • 英単語と日本語を登録でき、空のときと同じ英単語のときにメッセージが出ることを再現できる。
  • 登録した単語がカード画面に出る。カードを送ると答えが隠れた状態に戻ることを確かめられる。
  • 単語を追加したときに一覧が自動で変わる理由を、LiveData という言葉を使って説明できる。A10で setText を書いていたことと対比できる。
  • アプリを完全に終了して開き直しても単語が残ることを確かめられる。
  • STEP 07の練習1〜3でコードを消したあと、完成版に戻してRunし、追加した単語がその場で一覧に出ること、単語が0件のときに「次へ」が押せないことを確認する。
