教員用ガイド
RockPaperScissorsGame

画像リソース、配列とfor文、乱数、switch文による勝敗判定、連勝数を、学生が動作確認しながら積み上げる進行案です。90分×3コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/rock-paper-scissors-game/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A03RockPaperScissorsGame、パッケージは jp.ac.jec.a03rockpaperscissorsgame です。
  • STEP 2で使う title_image.png・rock.png・scissors.png・paper.png は、完成版ZIPの app/src/main/res/drawable から学生自身がコピーします。別の画像配布は行いません。
  • 完成版は Documents/Android1/samples/A03RockPaperScissorsGame に置きます。画像の貼り付け先とRunするプロジェクトが samples 側になっていないか、保存先で確認します。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a を縦向きで使います。横向きではボタンやCPUの手が画面外に出るため、今回の保証範囲に含めません。
  • 教員用の途中コードは teacher/rock-paper-scissors-game/code にあります。学生には配布せず、現在のSTEPの照合に使います。

今回の仕様上の制約

勝負！のあとは手の画像を setClickable(false) で押せなくし、次の戦いへで戻します。連勝数 winCount は次の戦いへでは保持し、引き分け・負けで0に戻します。各単元では画面回転時のデータ保持を扱いません。回転などでActivityが再生成された場合は、選択と連勝数が初期状態に戻ります。考え方と対処法は共通資料：開発TipsのC章に掲載しています。

2. この単元の教材方針

この単元は、READMEの「単元の範囲の決め方（全単元共通）」を明文化する前に作りました。次の表には、PR・issue・READMEに理由が残っている判断だけを載せています。学生から「ネットで見た書き方と違う」「前の単元と書き方が違う」と質問が出たときの答えになります。

方針理由授業での扱い
勝敗の判定はクリックの処理の中に書いたままにする。メソッドに切り出さないレビューで判定のテストがないと指摘されたが、テストには判定を別のクラスやメソッドへ切り出す必要があり、教材の「1ファイルで流れを追える」構成が変わる。A01・A02と同じく、動作はエミュレータとLogcatで確かめる。Unit Testは考慮しない方針（PR #7）。STEP 8で、画面の結果とLogcatの番号を、3×3の表と見比べる。STEP 9練習1でCPUの手を固定し、3通りを確かめる。
「次の戦いへ」でメッセージも初期表示に戻す。連勝数は戻さない最初の完成コードは、メッセージだけ前回の結果が残った。手を選ぶ画面に「あなたの勝ち」が出たままだと、勝負済みと誤解されるおそれがある。A02のリセットも、メッセージを初期化している。連勝数は保持するので、仕様は変わらない（PR #7、e0fe378）。STEP 7の表で、戻すものを1つずつ確認する。連勝数を戻さないことは、STEP 8①で説明する。
画像4枚は別に配布せず、完成版ZIPから学生がコピーする完成版は初回から公開するので、画像を別に配ると二重管理になる（PR #9）。STEP 2で、Copy画面の To directory に samples が入っていないことを、全員で確認する。
3つの手の画像は、配列の初期化子の中で findViewById を呼ぶ全単元共通のルールでは、findViewById は onCreate の冒頭でまとめて呼ぶ。配列の初期化子の中で呼ぶ形は、冒頭で取得していれば準拠とみなす例外として、READMEに明文化している（issue #21、PR #25）。STEP 5②で、配列にまとめる形をそのまま示す。{ } に書いた順番が、そのまま手の番号になる。
一番外側に android:padding を書かない。左右に余白のない見た目を許容する最初の完成コードの android:padding="12dp" は、ひな形の v.setPadding(...) が実行時に置き換えるため、効いていなかった。Previewには出るのに実機では消え、初学者には原因を特定できない。削除しても実機の見た目は変わらない（issue #23、PR #25）。余白を付けたいという質問には、共通資料：開発TipsのA章を案内する。

完成コードを説明するときの注意

btnStart と btnNext は、txtMessage や imgCpu と違ってキャストしていません。教科書STEP 5②は「クリック登録と有効・無効の切り替えだけを使うため、A02と同じくキャストしない」と説明しています。勝負！の処理には item という名前の変数が2つ出てきます。教科書STEP 6の「2つのitemは別の変数」で説明しています。完成コードの書き方は変えません。教科書で説明します。

5. 理解確認と支援

問い期待する行動・答え
押した手の番号はどこで決まる？内側のfor文の imageViews[i] == v がtrueのときに selectedHand = i を実行する、と示す。
CPUの画像の配列とimageViewsの順番をそろえる理由は？同じ番号が同じ手を表さないと、勝敗の計算が合わなくなる、と答える。
+ 3 がないと？自分の番号がCPUより小さいとマイナスになり、どのcaseにも入らない。STEP 9練習2の結果で説明する。
勝負！のあとに選び直せないのは？勝負！の処理の setClickable(false) を示し、次の戦いへの setClickable(true) と対応付ける。
回転したら？この単元では状態を保存しないため、選択と連勝数が初期状態に戻る、と理解している。

エラー時は「STEP番号・ファイル・最初の赤い行・操作順」を聞きます。A03のLogcat検索は、エラーが package:jp.ac.jec.a03rockpaperscissorsgame level:ERROR、STEP 8の判定ログが package:jp.ac.jec.a03rockpaperscissorsgame tag:MainActivity level:DEBUG です。

画像関係のエラーは、drawable以外への貼り付け、samples 側への貼り付け、ファイル名の変更（大文字・拡張子の重複）が主な原因です。Project表示で app/src/main/res/drawable を開いて確認します。

6. 到達度

  • 学生自身が手を選んで勝負！し、次の戦いへで何度も遊べる。
  • selectedHand と winCount の役割と、フィールドにした理由を説明できる。
  • CPUの手を固定したSTEP 9練習1で、3通りの結果と連勝数の増え方を確認できる。
  • STEP 9の変更を試したあと、完成版の値に戻してRunする。

7. 教材の保守と確認

  • 完成コードを変更したら、教科書の部分コード、完成コード、teacher/rock-paper-scissors-game/code、画像、練習の答えをまとめて確認し、python3 scripts/package-hello-android.py --project A03RockPaperScissorsGame --output docs/rock-paper-scissors-game/downloads/A03RockPaperScissorsGame.zip で配布用ZIPを再作成します。
  • アプリ画像は教員の jec_26cm_android1_Pixel 9a で撮影した、起動直後・グー選択・1連勝・2連勝の4状態です。次の戦いへの後は起動直後と同じ表示のため、起動直後の画像を使います。
  • 新規プロジェクト作成とdrawableへの画像追加の画像は教員提供資料を使用しています。
  • 印刷時は補足・解答も展開されます。解答を配布したくない場合は、ブラウザで授業中に開く方式を使ってください。
