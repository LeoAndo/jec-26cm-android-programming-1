ANDROID PROGRAMMING 1 / 授業サポート

教員用ガイド
BombGame

ボタンの配列、メソッドとdo-while文による重ならない乱数、定数による状態の管理、anyMatchによる判定、クリア条件を、学生がLogcatで確かめながら積み上げる進行案です。90分×3コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/bomb-game/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A05BombGame、パッケージは jp.ac.jec.a05bombgame です。
  • STEP 2で使う bomb_initial.png・bomb_ignited.png・bomb_exploded.png は、完成版ZIPの app/src/main/res/drawable から学生自身がコピーします。別の画像配布は行いません。
  • 完成版は Documents/Android1/samples/A05BombGame に置きます。画像の貼り付け先とRunするプロジェクトが samples 側になっていないか、保存先で確認します。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a を縦向きで使います。横向きではメッセージと再挑戦ボタンが画面に収まらず、ゲーム終了後に再挑戦を押せなくなるため、今回の保証範囲に含めません。
  • 教員用の途中コードは teacher/bomb-game/code にあります。学生には配布せず、現在のSTEPの照合に使います。

今回の仕様上の制約

押した数字ボタンは setEnabled(false) で押せなくし、爆発・クリアのときは9個すべてを押せなくします。着火したあとにクリアした場合、爆弾は火がついた画像のままです。導火線スイッチの数字は Log.d でLogcatに出すため、学生は動作確認に使えます。各単元では画面回転時のデータ保持を扱いません。回転などでActivityが再生成された場合は、押したボタンと状態が初期化され、スイッチの数字も選び直されます。考え方と対処法は共通資料：開発TipsのC章に掲載しています。

2. この単元の教材方針

この単元は、READMEの「単元の範囲の決め方（全単元共通）」を明文化する前に作りました。次の表には、PR・issue・READMEに理由が残っている判断だけを載せています。学生から「ネットで見た書き方と違う」「前の単元と書き方が違う」と質問が出たときの答えになります。

方針理由授業での扱い
Stream API（distinct / count / anyMatch / forEach / filter）をfor文に書き換えないA01〜A03にない書き方で、レビューでは、学生がコードを追えなくなりやすいと指摘された。オーナーの判断で、コードは変えずに教科書で解説すると決めた（PR #11）。for文にすると、フラグ変数と break、数える変数が要り、行数と入れ子が増える。追いにくさはfor文版にもある。STEP 5・7・9で1つずつ、表を使って説明する。forEach は、学習済みの拡張for文と同じ動きだと示す。つまずきが多ければ、for文版を練習問題に足すか、別のissueで検討する（PR #11の申し送り）。
スイッチの数字は、メソッドの中からフィールドに直接代入する最初の完成コードは、フィールドと同じ名前のローカル変数と this. を使っていた。そのまま教科書にすると、new int[2] の初期値と this. の説明が増え、学習目標（乱数・do-while文・状態の管理）から外れる。A02の answer も、メソッドの中から直接代入している（PR #11、42e62e9）。STEP 5②の表で「作った配列を、①のフィールドに入れる」と説明する。初期値はないが、クリックの処理を付ける前に onCreate で必ず代入される。
クリアの条件を括弧で囲み、7個・8個の意味をコメントに書く&& が先に計算されるので、括弧がなくても判定は同じ。ただ、学生が写し間違えたときに気付きにくく、7 と 8 の意味もコードから読み取れない。括弧があると、教科書の説明とコードの形がそろう（PR #11、42e62e9）。STEP 9「クリアの条件を読む」の表を読み合わせる。8と比べる理由は、STEP 10練習2（8を7に変える）で確かめさせる。
ログは Log.d にそろえ、スイッチの確認に使うA01・A03と共通資料：Logcatは、Log.d と level:DEBUG で統一している。最初の完成コードは、ここだけ Log.i だった。そろえると、検索欄がほかの単元と同じまま使え、「ここだけInfoの理由」の説明が要らない（PR #11、42e62e9）。STEP 5で、ログが2行出ることを確かめる。STEP 7・9は、このログでスイッチを見ながら、着火・爆発・クリアを試す。
9個の数字ボタンは、配列の初期化子の中で findViewById を呼ぶ全単元共通のルールでは、findViewById は onCreate の冒頭でまとめて呼ぶ。配列の初期化子の中で呼ぶ形は、冒頭で取得していれば準拠とみなす例外として、READMEに明文化している（issue #21、PR #25）。STEP 6①で、配列にまとめる形をそのまま示す。A03の imageViews と同じ書き方。
画像3枚は別に配布せず、完成版ZIPから学生がコピーするA03と同じ方式。完成版は初回から公開するので、画像を別に配ると二重管理になる（A03のPR #9）。STEP 2は「A03と同じ手順」と伝え、貼り付け先が samples 側でないかを確認する。
教科書の冒頭のタグは「A01〜A03の内容を使う」のままA04の教科書を追加したとき、上部にある前の単元へのリンクはA04に変えたが、タグは変えなかった。学習内容はA01〜A03を使い、A04（WebView）の内容は使わないため（PR #17）。STEP 0の冒頭で、A01〜A03の何を使うか（画面・配列とfor文・乱数・フィールド）を確認する。

完成コードを説明するときの注意

クリア判定の else { // ゲーム続行 には、爆発（ゲームオーバー）の表示も含まれます。教科書STEP 9では「クリアではないとき」と説明しています。btnRetry は、txtMessage や imgBomb と違ってキャストしていません。教科書STEP 6①は「クリック登録と表示の切り替えだけを使うため、A03と同じくキャストしない」と説明しています。if (match) nowState++; の { } の省略は、STEP 7②の表で説明しています。Stream APIを含め、完成コードの書き方は変えません。教科書で説明します。

5. 理解確認と支援

問い期待する行動・答え
2つのスイッチが同じ数字にならないのは？do-while文の条件 distinct().count() != 2 を示し、同じ数字なら作り直す、と答える。
押した数字がスイッチかは、どこで調べる？anyMatch(num -> num == number) を示し、配列に同じ値が1つでもあればtrue、と答える。
nowState++ で次の状態になるのはなぜ？定数が STATE_INITIAL = 1、STATE_IGNITED = 2、STATE_EXPLODED = 3 の連番だから、と答える。
着火後は8と比べるのはなぜ？押したスイッチ1個も押せないボタンに数えるため。STEP 10練習2の結果で説明する。
再挑戦でスイッチが変わるのは？再挑戦の処理から generateIgnitionNumbers() を呼んでいる、と示す。
回転したら？この単元では状態を保存しないため、押したボタンと状態が初期化され、スイッチも選び直される、と理解している。

エラー時は「STEP番号・ファイル・最初の赤い行・操作順」を聞きます。A05のLogcat検索は、エラーが package:jp.ac.jec.a05bombgame level:ERROR、STEP 5のスイッチのログが package:jp.ac.jec.a05bombgame tag:MainActivity level:DEBUG です。

画像関係のエラーは、drawable以外への貼り付け、samples 側への貼り付け、ファイル名の変更（大文字・拡張子の重複）が主な原因です。nowState を onCreate の中で宣言すると、ラムダの中で変更できないエラーになります。フィールドの位置を確認させます。
