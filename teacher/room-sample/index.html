教員用ガイド
RoomSample

A09の SharedPreferences ではできなかった「1件だけ書き換え・1件だけ削除」を、Roomで実現する単元です。新出概念は Room だけ。90分×1コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/room-sample/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A10RoomSample、パッケージは jp.ac.jec.a10roomsample です。
  • 配布物はありません。画像も外部ファイルも使いません。
  • 完成版は Documents/Android1/samples/A10RoomSample に置きます。見本と学生のアプリは同じパッケージ名のため、端末上では同じアプリを上書きします。保存したデータも共有されます。見本でデータを入れたあとに学生のアプリをRunすると、学生側の初回起動で一覧にデータが入った状態になります。STEP 07の「一覧が空から始まる」を見せる前に、学生の端末でアプリのデータを消去させてください。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a を縦向きで使います。
  • STEP 02で初めてライブラリを追加します。Syncにネット接続が必要です。授業前に一度、教員機でSyncを通してキャッシュを作っておくと、全員が同時にダウンロードする事態を避けられます。
  • アプリの実行にインターネット接続は不要です。この単元ではLogcatを使いません。

今回の仕様上の制約

一覧は TextView に toString() の結果を並べただけです。行をタップして選ぶことはできません。行の選択には RecyclerView が必要で、README 基本方針7によりAndroidプログラミング1では扱いません。画面回転時の入力欄の保持も扱いません（共通資料：開発TipsのC章）。保存したデータは画面を回しても消えません。ここはA09との違いとして説明に使えます。

2. この単元の教材方針

README「単元の範囲の決め方（全単元共通）」に沿って範囲を絞っています。新概念は Room 1つだけです。次の表は、Roomの一般的な入門コードから意図的に外したものと、その理由です。学生から「ネットで見た書き方と違う」と質問が出たときの答えになります。

外したもの理由授業での扱い
synchronized によるDouble-checked lockingこの単元は allowMainThreadQueries() で読み書きを画面と同じ流れに寄せており、競合する相手のスレッドが存在しない。ロックを入れても画面上は何も変わらず、基準2（利点を画面で体感できる形にする）を満たせない。STEP 06の解説では「1つだけ作って使い回す」だけを扱う。質問が出たら「複数の流れから同時に触るときに必要になる」とだけ答える。
@Insert と @Update2つを使い分ける判断が増えるだけで、画面の動きは @Upsert 1つで説明しきれる。「idが空なら追加、入れたら書き換え」という画面の動きが、メソッド1つに対応する。STEP 05の解説で、Roomには3つあることと、この授業では1つに絞っていることを明示する。
LiveData単一画面では、書いたあとに setText し直すのと見た目が変わらず、利点を体感できない。A11VocabularyBookで、複数画面の同期という体感できる形にして導入する。
@ColumnInfo(name = "...")列名を別名にする必要がない。フィールド名がそのまま列名になるほうが、@Query のSQLとJavaのフィールドが1対1で読める。扱わない。
可変長引数（insert(Item... items)）画面から渡すのは常に1件。可変長引数の記法を説明する必要が生じるだけ。扱わない。
description などの追加フィールド項目を増やしても、覚えることは増えず入力の手間だけ増える（基準3）。internalId と title の2つだけにする。

方針の例外：@NonNull を学生に書かせます

READMEの全単元共通ルールでは、@NonNull / @Nullable を学生自身が書く実装では扱いません。この単元の Item.java だけは例外です。

@Entity のフィールドに付けた @NonNull は、Javaの注意書きではなく「この列は NOT NULL である」という表の定義そのものです。外すと表の形が変わり、Roomが生成するSQLも変わります。「書かなくてよい注釈」ではないため、ここだけは書かせます。

STEP 04の解説にこの説明を入れています。この説明を飛ばすと、他単元で「書かなくてよい」と言ったこととの矛盾だけが残ります。あわせて、ItemDao の @Nullable（見つからないことがある、の意味）も同じ枠で扱ってください。

完成コードを説明するときの注意

var、ラムダ式、findViewById の明示キャスト、Snackbar の書き方は変えません。単元をまたいで同じ形にそろえるためです（READMEの「完成コードの書き方（全単元共通）」）。

3. 90分×1コマの進行

時間配分終了時の確認
STEP 00：5分、STEP 01：10分、STEP 02：10分、STEP 03：10分、STEP 04：15分、STEP 05：15分、STEP 06：10分、STEP 07：25分保存・書き換え・削除ができ、アプリを終了して開き直してもデータが残る。

STEP 02が最初の関門です。libs.versions.toml の [libraries] と [plugins] を取り違える間違いが必ず出ます。[plugins] 側に書くと expected to find any of 'id' or 'version' でビルドが止まります。教科書に注意書きを入れていますが、机間指導では追記した行のすぐ上の見出しを指差して確認させてください。

STEP 05でInterfaceを選び間違える学生が出ます。ItemDao だけ Interface、Item と AppDatabase は Class です。Classで作ってしまうと、中身を貼り付けた瞬間に赤いエラーが並びます。作り直させるのがいちばん早いです。

STEP 04〜06は「書いて、Syncして、まだ画面は変わらない」が3回続きます。学生の手応えが途切れる区間です。STEP 03の終わりで「ここから3つ部品を作る。画面が動くのはSTEP 07」と先に伝えておくと、迷子になりません。

時間が余ったら、STEP 07の練習1〜3とふり返り5問を回します。練習3（setText を消す）は「データベースには書けているが画面に出ていない」という状態を作れるので、A09の「保存と表示は別物」の再確認になります。
