教員用ガイド
WebViewApp

テーマとManifestの設定、WebView、enumとオプションメニュー、JavaScriptの設定、Android 16以降の戻る操作を、学生が動作確認しながら積み上げる進行案です。90分×2コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/webview-app/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A04WebViewApp、パッケージは jp.ac.jec.a04webviewapp です。
  • アプリの実行中にインターネット接続が必要です。教室のネットワークで、メニューの4サイト（Yahoo!ニュース、GitHub Copilot、映画「SLAM DUNK」公式サイト、OpenAI ChatGPT）とSTEP 9練習1の https://www.jec.ac.jp/ が表示できるか、事前に確認します。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a（教材撮影用はAndroid 17）を縦向きで使います。STEP 8の「戻る」はAndroid 16以降の動作変更に関わるため、学生のエミュレータがAndroid 15以前の場合は、STEP 9練習3の結果が教科書と異なります（前のページに戻れる）。
  • 完成版は Documents/Android1/samples/A04WebViewApp に置きます。学生の作成先と混同しないよう、Run前に保存先を確認します。
  • 教員用の途中コードは teacher/webview-app/code にあります。学生には配布せず、現在のSTEPの照合に使います。

今回の仕様上の制約

起動直後はページを読み込まず、白い画面から ⋮ でサイトを選びます。「javaScript ON」は起動時にチェックなし（JavaScript無効）で、切り替えるたびに reload() します。各単元では画面回転時のデータ保持を扱いません。回転などでActivityが再生成された場合、表示中のページと戻る履歴は初期状態に戻ります。この観点は別単元の演習アプリで検証します。

STEP 8は、コードを入れる前に「今のままだと戻る操作でホーム画面に戻ってしまう」ことを全員で確かめてから始めると、変更の目的が伝わりやすくなります。

4. 理解確認と支援

問い期待する行動・答え
INTERNETの許可がないと？「ウェブページへのアクセス不可」net::ERR_CACHE_MISS になる、と答える。Manifestの1行を指させる。
メニューを押したとき、どのURLかはどう決まる？menu.add の2つ目の引数に ordinal() をidとして渡し、values()[item.getItemId()] で同じ値を取り出す、と示す。
サイトを増やすには？AppMenuItemに値を1つ追加するだけで、MainActivityは変えなくてよい。STEP 9練習1で確かめる。
enumを使わず、URLと表示名を配列2つで持つと何が困る？足す位置がずれると押した項目と違うサイトが開き、titlesに足してurlsに足し忘れると実行中のエラー（ArrayIndexOutOfBoundsException）でアプリが閉じる（urlsだけに足すと5つ目の項目がメニューに出ない）。どれも赤いエラーにならない。enumなら1つのサイトの情報が1行にまとまり、AppMenuItem.YAHO のような打ち間違いは赤いエラーになる、と答える。URLの文字そのものの誤りと、values()[7] のようなない番号は、enumでも赤いエラーにならない点も補足する（STEP 5の解説）。
setWebViewClientがないと？ページ内のリンクでChromeが開く。STEP 9練習2の結果で説明する。
なぜonKeyDownではなくOnBackPressedCallback？targetSdk 36以上のアプリをAndroid 16以降で動かすと、KEYCODE_BACKが届かない。予測型「戻る」のため、戻る処理が有効かを先に登録する必要がある、と答える。
最初は無効（false）にする理由は？前のページがないときはAndroidの通常の戻る操作（ホーム画面に戻る・そのプレビュー）に任せるため。
回転したら？この単元では状態を保存しないため、表示中のページと履歴が初期状態に戻る、と理解している。

エラー時は「STEP番号・ファイル・最初の赤い行・操作順」を聞きます。A04のLogcat検索は package:jp.ac.jec.a04webviewapp level:ERROR です。

ページが表示されない場合は、エラー画面の文字でアプリ側（許可）とネットワーク側を切り分けます。net::ERR_CACHE_MISS はINTERNETの許可の行がない・つづりが違う・未保存のいずれか、それ以外のエラー名はMacやエミュレータの接続状態を先に確認します。許可の行の位置の誤りはビルドエラーとして現れます。

5. STEP 8の背景：戻る操作の実装を変更した理由

完成プロジェクトの最初の実装（PR #10のbb2b778）では、onKeyDown で KEYCODE_BACK を受け取り、webView.goBack() していました。Android 15以前の端末では動作しますが、targetSdk 36以上のアプリをAndroid 16以降で動かすと、予測型「戻る」が既定で有効になり、onBackPressed は呼ばれず、KEYCODE_BACK も届きません。

  • 本プロジェクトは targetSdk = 36、教材撮影用の jec_26cm_android1_Pixel 9a はAndroid 17（API 37）です。bb2b778では、前のページがあっても戻る操作でホーム画面に戻ることを確認しました。
  • 修正版は OnBackPressedCallback(false) を登録し、WebViewClient#doUpdateVisitedHistory で canGoBack() のときだけ有効にします。キー入力と左端からのスワイプの両方で、前のページに戻ること、最初のページではホーム画面に戻ることを確認しています。
  • コールバックを常に有効（true）にする書き方は、前のページがないときに戻る操作でホーム画面に戻れなくなり、そのプレビューも出なくなるため採用していません。
  • android:enableOnBackInvokedCallback="false" で以前の動作に戻す方法は、公式資料で一時的な回避策とされているため、教材では「使わない」と紹介するだけにしています。

学生向けの解説は、教科書STEP 8の「解説：Android 16から『戻る』の受け取り方が変わった」にあります。ネット上の記事や公式のWebView資料には onKeyDown の例が残っているため、授業ではSTEP 9練習3で、学生自身が以前の書き方では戻れないことを確かめます。

参照：Android 16の動作変更、予測型「戻る」ジェスチャーのサポート、WebView内のページ履歴の移動。

6. 到達度と提出

  • 学生自身が ⋮ から4つのサイトを開き、ページ内のリンクで移動し、戻る操作で前のページに戻れる。
  • INTERNETの許可・テーマの変更を行ったファイルを指させる。
  • AppMenuItemの値とordinal、メニューのidの対応を説明できる。
  • 配列を2つ使う書き方と比べて、enumを使うメリット（打ち間違いがエラーになる、情報が1行にまとまる、追加がenumだけで済む、名前で読める）を1つ以上説明できる。
  • onKeyDown ではなく OnBackPressedCallback を使う理由を、Android 16の変更と結び付けて説明できる。
  • STEP 9の変更を試したあと、完成版のコードに戻してRunする。
  • 提出する場合は 共通資料：APKの作り方に従い、先生が指定した場所へ 学籍番号_A04WebViewApp.apk を提出する。
