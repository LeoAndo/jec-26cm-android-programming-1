教員用ガイド
SharedPreferencesSample

「アプリを終了しても消えないデータ」を、SharedPreferences で体験させる単元です。保存・読み出し・初期値・削除の4つに絞り、最後に保存先のXMLファイルをアプリ自身に表示させて、データがどこにどう残るのかを目で確かめさせます。90分×2コマを目安に調整します。

1. 授業前の準備

  • 学生用の入口は docs/shared-preferences-sample/index.html です。完成版ZIPと画像を含む教材を、構成を保って配布します。
  • Android Studio Panda 2 | 2025.3.2、Java / Empty Views Activity、Minimum SDK API 31を確認します。作成先は Documents/Android1/A08SharedPreferencesSample、パッケージは jp.ac.jec.a08sharedpreferencessample です。
  • 配布物はありません。画像ファイルも外部ライブラリも使いません。学生は教科書のコードを入力するだけです。
  • 完成版は Documents/Android1/samples/A08SharedPreferencesSample に置きます。見本と学生のアプリは同じパッケージ名のため、端末上では同じアプリを上書きします。保存データも共有される点に注意してください。見本でapplyしたあとに学生のアプリをRunすると、学生側の初回起動で値が入った状態になります。STEP 04の「初期値が出る」を見せる前に、学生の端末で一度clearするか、アプリのデータを消去させます。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a を縦向きで使います。
  • アプリの実行にインターネット接続は不要です。この単元ではLogcatを使いません。結果はすべて画面に表示されます。

今回の仕様上の制約

各単元では画面回転時のデータ保持と横画面のレイアウトを扱いません。ただし今回のデータは SharedPreferences にあるため、回転しても端末を再起動しても残ります。回転で失われるのは画面に表示していた文字だけで、保存データではありません。この違いは質問が出たときに扱います。

2. この単元の教材方針

方針理由授業での扱い
Logcatを使わない。結果はすべてアプリの画面に出すコマンド操作やIDEの機能に不慣れな学生、日本語のログ文言が読みにくい留学生でも、アプリを動かすだけで結果を確認できる。確認手段の習得が単元の主題を邪魔しない。STEP 00で「今日はLogcatを開きません」と明言する。アプリが終了したときだけ level:ERROR で確認させる。
保存先のXMLをアプリ自身に表示させる（STEP 08）Device Explorerや adb は、この受講者像にはハードルが高い。アプリは自分のデータディレクトリを権限なしで読めるので、実機でもそのまま動く。表示されるのは記号と英数字だけで、言語にほぼ依存しない。STEP 08がこの単元の山場。apply後とclear後の2回表示させ、<map /> になることを確かめさせる。
OnSharedPreferenceChangeListener、commit()、remove() は扱わないリスナはライフサイクルと解除の話が必要で、主題が2つになる。remove() は clear() と考え方が同じ。範囲を保存・読み出し・初期値・削除の4つに絞る。commit() は教科書の解説（applyとcommitの違い）で表だけ示し、コードは書かせない。
保存は apply() に統一する実務で使うのは apply()。1つの単元で2つの書き方を出すと、どちらを使うべきか迷わせる。clear() の確定も apply() で統一している。
キーは private static final String でMainActivityに置くこの単元のクラスはMainActivityだけ。専用の定数クラスに分けると、使う側が1つしかないのに間接参照が増える。private に閉じられる利点もある。複数の画面で共有する場合の置き場所は、質問が出たときだけ触れる。
表示欄に layout_weight="1" を付けるwrap_content だと表示内容の長さでボタンの位置が上下に動き、押し間違える。ボタンを何度も押す教材のため。STEP 02の解説で理由を扱う。「なぜweightを付けるのか」は設計の話として短く。

完成コードを説明するときの注意

var、ラムダ式、Set.of()、Files.readAllBytes の書き方は変えません。教科書で説明します。readPrefsXml() の try〜catch (IOException e) は「ファイルを読めなかったときに受け止める」とだけ説明し、例外処理の一般論には広げません。getApplicationInfo().dataDir は「このアプリ専用の場所」とだけ触れます。

3. 90分×2コマの進行

コマ時間配分終了時の確認
1コマ目STEP 00：5分、STEP 01：15分、STEP 02：15分、STEP 03：10分、STEP 04：20分、STEP 05：20分、個別支援：5分applyを押すと6行の値が変わる。押す前は初期値が出ることを説明できる。
2コマ目再開：5分、STEP 06：15分、STEP 07：10分、STEP 08：20分、STEP 09：15分、STEP 10：15分、個別支援：10分終了して開き直しても値が残る。app.xmlの中身を表示でき、clearで <map /> になることを確かめられる。

STEP 04は、まだ何も保存していない状態で読み出すことに意味があります。ここを飛ばしてSTEP 05のapplyを先に押させると、初期値を見る機会がなくなります。順番どおり進めさせてください。

STEP 06は、この単元でいちばん大事な確認です。アプリの終了は「最近使ったアプリ」から上へスワイプで行わせます。戻る操作（◁）だけでは終了しないことがあり、「残った」ように見えて確認になりません。全員が終了→起動を2回できたことを確かめてから次へ進みます。

STEP 08は、readPrefsXml() を onCreate の中に貼ってしまう誤りが起きやすい工程です（A06・A07と同じ）。「onCreateの最後の } の下」を板書か画面で示します。まだ一度もapplyしていない端末では (file not found) が出ます。これは正常で、ファイルは最初のapplyのときに作られることを説明する機会になります。

時間が足りない場合は、STEP 09のミニ練習を口頭の問いかけに切り替えます。練習2（初期値を -1 に変える）だけは、STEP 04の理解確認に直結するため残すことを勧めます。

5. 理解確認と支援

問い期待する行動・答え
アプリを終了しても値が残るのはなぜか。A07までと何が違うかapply() のときに端末の中のファイルに書き込んでいるから、と答える。A07までの値はメモリの上にだけあり、終了すると消えていた。
edit() → putInt → apply() のうち、どれを忘れると保存されないかapply()。putだけでは保存されない、と答える。edit() を忘れた場合はコンパイルできない。
getInt(INT_VALUE, 0) の 0 はいつ使われるかそのキーのデータが保存されていないときだけ、と答える。保存されていればその値が返る。
画面に int_value = 0 と出ているとき、0が保存されているか画面だけでは判別できない、と答える。show app.xmlで <int name="int_value" ...> があるかを見れば分かる。
キーを定数にまとめているのはなぜか保存と読み出しで同じ文字を使う必要があり、直接書くと打ち間違えても赤いエラーにならないため、と答える（STEP 09練習3）。
FILE_NAME = "app" はどこに現れるか保存先が shared_prefs/app.xml になる、と答える。show app.xmlのパスで確かめられる。
MODE_PRIVATE の意味はこのアプリだけが読み書きできる、と答える。
SharedPreferences にパスワードを保存してはいけないのはなぜか中身が暗号化されていないただのXMLファイルだから、と答える。STEP 08で実際に中身を見ていることを根拠にできる。
clearするとファイルはどうなるかファイルは残り、中身が <map /> になる、と答える。

エラー時は「STEP番号・ファイル・最初の赤い行・操作順」を聞きます。この単元のLogcat検索は package:jp.ac.jec.a08sharedpreferencessample level:ERROR です（共通資料：Logcat）。

よくある原因は、①editor.apply() を書き忘れた（何も保存されない）、②currentValues() や readPrefsXml() を onCreate の中に貼った（赤いエラーが大量に出る）、③prefs = getSharedPreferences(...) を txtOutput.setText(currentValues()); より下に書いた（起動時にアプリが終了する）、④R.id の名前の取り違え（ボタンを押しても何も起きない）、⑤レイアウトの txt_output を wrap_content のままにした（ボタンの位置が動く）、の5つです。

③はNullPointerExceptionで起動直後に終了します。画面に何も出ないため学生は原因をつかみにくいので、onCreateの中の行の順番を最初に確認させてください。

6. 到達度

  • applyで6種類の値を保存し、アプリを完全に終了して開き直しても残ることを自分で再現できる。
  • 保存していない状態で getXxx が初期値を返すことを説明できる。「表示が0」と「0が保存されている」が別であることを説明できる。
  • show app.xmlでファイルのパスと中身を表示し、キーがname・値がvalueとして記録されていることを説明できる。
  • clearで全削除でき、そのあとファイルが <map /> になることを確かめられる。
