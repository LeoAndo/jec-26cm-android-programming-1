授業内で「操作・確認・言語化」まで終えるための進行案です。1コマ90分、全2コマを目安に、クラスの進み具合に合わせて調整します。

1. 授業前の準備

  • 学生には、完成プロジェクトのZIPを含む docs フォルダを、構成を保って配布します。完成版は初回から自由に参照できます。teacher フォルダと教員のひな形プロジェクトは配布しません。
  • 学生のMacで docs/hello-android/index.html をブラウザで開けることを確認します。公式資料以外にCDN・Webフォント・オンライン実行環境は使いません。
  • Android Studio Panda 2 | 2025.3.2、必要なSDK・System Image・Gradle依存関係を事前にそろえます。初回ダウンロードは下表の授業時間に含めません。
  • Panda2JavaEmptyViewActivity は、教員が出発点を確認するために使います。学生はAndroid StudioのJava / Empty Views Activityから A01HelloAndroid を新規作成します。
  • 学生の作成先を /Users/ユーザ名/Documents/Android1/プロジェクト名 に統一します。画像の教員のパスを写さないよう、本人のユーザ名と末尾のフォルダを確認します。
  • Project表示でファイルを開きます。Auto Importの共通資料に従って、授業前にJava欄の設定を確認します。
  • 指定エミュレータ jec_26cm_android1_Pixel 9a で完成版をRunし、文字変更・Snackbar・Toast・Logcatを確認します。
  • 本日の停止位置を板書します。

完成版を公開して進める

各単元で、学生自身が毎回Android Studioからプロジェクトを新規作成することを固定方針とします。完成版は、動く状態の確認と、自分のコードとの比較に使います。見本を読むときは今のステップの部分を指定します。理解は、STEP 8の小変更と、結果の実演・指さし・短い説明で確認します。

見本の置き場所は Documents/Android1/samples/A01HelloAndroid、学生が作る場所は Documents/Android1/A01HelloAndroid です。学生向けの完成版の開き方を初回に案内します。

2. この単元の教材方針

方針理由授業での扱い
ひな形の ConstraintLayout を、LinearLayout に全体ごと置き換える部品を縦に並べやすいため（教科書STEP 3の説明）。STEP 3②で、古いXMLに追加させず、ファイル全体を置き換えさせる。id/main はひな形のJavaでも使っているので、消さずに残すよう伝える。
表示する文字は strings.xml に移さず、XMLとJavaに直接書く。Hardcoded string などのLintの警告は直さないプログラミング初心者向けの90分×2コマで、編集する場所と学習する概念を抑える構成にしているため。文字列リソースへ移すと、strings.xml・Java・XML・途中段階のコード・配布ZIPを合わせて変更し、説明する必要があり、この単元の学習目標に対して負担が大きい。多言語対応やリソース管理を扱う段階での改善として扱う。Lintの警告も、初学者向けの教材なので細かい修正・調整はしないと決めている（どちらもPR #1 での判断）。STEP 3の「入力のポイント」で、「文字を直接書くと Hardcoded string という警告が出る場合があります。この単元では文字を直接書きます」と案内している。赤いエラーと警告を分けて見るよう伝える。
findViewById は、var と明示的なキャストで書くvar text = (TextView) findViewById(R.id.text); の形。var は、コード量を減らすために全単元で使う（README 基本方針8）。キャストはJavaとしては冗長だが、消さない。その行だけを読んだ学生にも、部品の型が見えるようにするため。STEP 4③の表で、(TextView)（キャスト）と var を1行ずつ説明している。A02以降の単元でも、同じ書き方を使う。
ボタン「3」には処理を付けない（XMLにidがなく、Javaにクリック処理もない）「1」はSnackbar、「2」はToast、「3」はボタンの見た目を比べるため、という構成にしているため。動作を足すと、教科書・途中段階のコード・完成版の学習内容を変えることになり、初学者向けの説明量も増える（PR #1 のレビューでの判断）。STEP 0で「押してもメッセージは出ません」と先に伝える。STEP 7の表では「3」を「処理を追加しない」としており、③で「3」を押してメッセージが出ないことを確かめさせる。

完成版を初回から公開して進める方針と、完成版にないライブラリを学生に追加させない方針は「1. 授業前の準備」に、授業の進め方は「4. 留学生・初心者への進め方」に書いています。画面再作成後の文字の保存を扱わないことは「6. 到達度の確認」にあります。

完成コードを説明するときの注意

var、ラムダ式（v -> { … }）、findViewById の明示キャストの書き方は変えません。単元をまたいで同じ形にそろえるためです（READMEの「完成コードの書き方（全単元共通）」）。

4. 留学生・初心者への進め方

  • 最初に完成動作を見せる。 1回の実演は「起動 → 変更 → 1 → 消えるのを待つ → 2」の順。操作と結果を同じ短い文で繰り返します。
  • 1回の指示は1つ。 「MainActivity.javaを開く」「追加する場所を見る」「2行追加する」と分けます。複数のファイルを同時に修正させません。
  • コード入力と意味の説明を分ける。 コピー後に、id・変数・処理の場所を指さして確認します。書き写しだけで完了とせず、予想と小変更で理解を見ます。
  • 英語のUI名を残す。 実画面と同じ表記を読み、日本語の短い意味を添えます。日本語の長い説明を暗記させません。
  • 止まれる場所を共有する。 各ステップの緑の確認欄で全員を待ちます。確認を終えた学生は、そのステップをもう一度自分で動かします。
  • 質問を定型にする。 「STEP __」「ファイル名」「赤い最初の行」。日本語で長く話せない場合は指さしや母語のメモから始められます。
  • 復習を授業内に置く。 STEP 8・9を必須とし、予習や自宅でのやり直しを前提にしません。

3のボタンに処理がないのは完成版の仕様です。画面再作成後の文字の保存はこの単元の対象に含めません。起動状態を確認するときはStop → Runで条件をそろえます。

チェックの保存はブラウザのlocalStorageを使い、送信はしません。ブラウザ・ファイルの移動・保存設定で記録が消える場合があるため、成績や提出の記録には使わず、STEP 9の記録を回収してください。
